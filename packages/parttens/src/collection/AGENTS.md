# Collection layouts pattern

Controlled renderers for one collection: the consumer declares a `CollectionDefinition` (`records`, `getKey`, `getLabel`, `groupings`), `CollectionProvider` holds the `{ layout, groupBy }` preferences, and `CollectionLayoutOutlet` mounts the active layout: `KanbanView`, `ListView`, `GalleryView`, `DataGrid`, `DataTable` or `CalendarView`, each also usable alone. Kanban and Calendar drag with dnd-kit and report the move, which the consumer accepts or rejects; Data Grid and Data Table run on TanStack Table v9 instances from `useDataGrid` and `useDataTable`. The pattern never fetches, sorts, persists or ships CSS; its only state is the uncontrolled preferences, optimistic drag overrides, list and grid collapse state, and the TanStack table state those hooks keep locally.

## Map

| Folder | Holds |
| --- | --- |
| `composition/` | `CollectionLayoutOutlet`: picks the layout, projects groups, adapts kanban moves to `onRecordChange`; `CollectionFrame`: the header, body and footer around a toolbar and a layout |
| `store/` | `CollectionProvider` and `useCollectionPreferences` |
| `types/` | the collection contracts (definition, grouping, group, preferences, record change) |
| `shared/components/` | toolbar pieces: search, view settings, filter submenu, presets, `Action`; `CollectionPagination`, the page bar for the frame footer, which `DataGridPagination` also renders (folded in from `packages/parttens/src/pagination/` on 2026-11-21, since `UI/Pagination` documents the base parts) |
| `shared/hooks/` | `useScrollbarInsets`, which Data Table and Data Grid use to start the vertical scrollbar below their sticky header and end it above their sticky footer |
| `shared/lib/` | `projectCollection`, the one function that turns a collection plus a grouping into groups; `skeleton-keys`; `interactive-descendants`, the selector the `ListRow` slots and the `DataTable` row use to keep controls clickable above a stretched trigger, and `interactiveControls`, the same list without `[tabindex]`, which `ListRow` uses to tell a control from a focusable property |
| `layouts/<layout>/` | `calendar`, `data-grid`, `data-table`, `gallery`, `kanban`, `list`; each with its own `index.ts` and a `README.md` holding its benchmark |
| `test/` | `test/dom.ts`, the JSDOM setup the tests import, and `test/jsdom.d.ts` |
| `core.ts` | React-free surface: collection, calendar, data-grid and kanban types, kanban drag helpers, date helpers; workspace only, not reached from the barrel |

`layouts/data-grid/` has its own `AGENTS.md` with its file map and invariants; read it before touching the grid.

Import direction: `composition/` → `store/`, `shared/lib/`, `types/` and the six layouts; each layout → its own folders and `types/`; list and kanban may also import `shared/lib/project-collection.ts`, list and data-table import `shared/lib/interactive-descendants.ts`, list and gallery import `shared/lib/skeleton-keys.ts`, data-table and data-grid import `shared/hooks/use-scrollbar-insets.ts`, data-grid imports `shared/components/collection-pagination.tsx` (from `layouts/data-grid/components/data-grid-pagination.tsx`), `shared/` and `store/` → `types/`; layouts never import each other. `shared/components/collection-pagination.tsx` imports only `@tc96/ui/pagination`, `@tc96/ui/button`, `@tc96/utils`, `@phosphor-icons/react` and React. Outside the folder, `layouts/data-grid/components/data-grid-selection-actions.tsx` imports `packages/parttens/src/action-bar/components/action-bar.tsx`, which makes the registry ship `action-bar/` with `collection`; nothing here imports `packages/parttens/src/toolbar/` at runtime, so `itemAreas` in `packages/registry/src/manifest.ts` makes the `collection` item ship it.

## Invariants

Collection and outlet:

- `CollectionLayoutOutlet` throws when the active layout is `list` (`renderListRecord`), `datagrid`, `datatable`, `calendar`, `gallery` (`renderGalleryRecord`) or `kanban` (`renderKanbanRecord`) and the matching prop is missing; `projectCollection` throws for `groupBy === null` and for an undeclared dimension. Tests assert the messages.
- Prepared `groups` win over `projectCollection` in list and kanban, and an explicit `[]` never falls back to the source records.
- `kanban.onMoveCard` receives the group of each side, so a handler never parses column ids; a column with no matching group rejects the move. Without it, drag is enabled by `onRecordChange` plus `setGroupId` on the active dimension, and a reorder inside one group returns false, because the collection order is the consumer's. `kanban.onMoveCard` wins when both are passed.

Kanban:

- A cross-column `dragOver` calls `event.preventDefault()` and goes through state: dnd-kit's optimistic DOM reorder moved the node outside React, which then failed in `removeChild`. Same-column reorders keep the dnd-kit plugin.
- When `onMoveCard` returns a promise, the dnd-kit suspension resumes immediately so the drop animation does not wait on the network. `false`, a rejection or a throw rolls back; `true` keeps the override until `columns` shows the card at the target.
- The whole card drags except interactive descendants; `KanbanCardOpenTrigger` drags only past 5px (touch: 250ms delay, 5px tolerance). The grip handle, visible only on focus, is the keyboard and assistive-technology activator.
- `KanbanView` always renders the mobile panel and the desktop board and lets CSS pick one, so the active column's cards render twice: `renderCard` must be pure and emit no DOM ids. Below `md` sorting is off; a collapsed column has no drop target.
- The board drag-scrolls only while card drag is enabled, and a click within 500ms of a drag is suppressed.
- `KanbanCard` is only structure: the root `article` and its slots, with no content props; the consumer fills each slot (decided on 2026-11-14 by the owner, replacing the props anatomy of the Pipeline card). `KanbanCardHeader` holds `KanbanCardTitle`, `KanbanCardDescription` and `KanbanCardAction`; `KanbanCardBody` is a two-column grid whose label column takes the widest `KanbanCardFieldLabel`, 8px before the values, one `KanbanCardField` per row; `KanbanCardFooter` sits 12px below the body. `KanbanCardFieldValue interactive` and `KanbanCardControl` raise a control above the open trigger. In `compact` the description, body and footer hide, so a consumer that wants the assignee there puts it in the header. `KanbanCardSkeleton` follows the card through `loadingCardAnatomy` (`descriptionLines`, `fields`, `counts`, `menu`, `assignee`), at the real line heights; the stories check that the loading card keeps the loaded height.
- `KanbanCard` stays an `article` (tested). `KanbanCardSkeleton`, `GalleryRowSkeleton` and `ListRowSkeleton` wrap the card in an `output` with `aria-busy`, because an `article` cannot be `status`. `KanbanBadge` accepts `tone` and ignores it.

Gallery, list, calendar and table:

- `GalleryView` renders the flat `collection.records` in source order and never groups, sorts or owns card anatomy. The grid has one column, two from `sm` and three from `lg`. It never paginates: `pageSize` (3, 6, 9 or 12, whole rows of three) only sizes the page the consumer passes, so loading renders that many skeletons and the grid reserves the rows of a full page (`minmax(13rem, auto)`, the card `min-h-52`) at each breakpoint, and a partial last page keeps the height. Each size maps to one complete class string, so the Tailwind scanner sees every class. Loading renders `loadingRecordCount` skeletons (four by default) shaped by `loadingRecordAnatomy` (`eyebrow`, `action`, `titleLines`, `descriptionLines`, `footer`, `density`), at the real line heights of the COSS `Card`, and an empty collection renders `emptyMessage` through the COSS `Empty` block.
- `ListView` renders the flat collection with `h2` titles and grouped lists with `h3`. An empty flat list (`grouping === null`, not loading) renders `emptyMessage` in the COSS `Empty` block, like an empty group. With `collapseEmptyGroups`, a manual choice wins, an untouched group reopens when it gets items, every group stays open while loading, and `onCollapsedGroupIdsChange` reports the effective list.
- `ListRow` is only structure: the root `article` and its `ListRow*` slots, with no content props; the consumer fills each slot. `ListRowTitleTrigger` stretches over the row (`after:absolute inset-0` against the `relative` root). `ListRowLeading` and `ListRowField` are `pointer-events-none` with `interactiveDescendants` raised, so a plain area reaches the trigger; a focusable that is not a control (a `tabindex="0"` span, such as `DateProperty` with `tooltip`) takes pointer events so its tooltip opens on hover, and a click on it is forwarded to the row's trigger with `.click()`, while a control (`interactiveControls`) keeps its click. Clicks that bubble through a portal (a popover inside a property) or were `preventDefault`ed are not forwarded. `ListRowAction` sits above the trigger with `z-10`. Both areas share one internal `PlainArea`, whose `onClick` carries the only comment in the layout, a `biome-ignore` for `noStaticElementInteractions` and `useKeyWithClickEvents`: the click is a mouse-only mirror of the trigger, which is the keyboard path.
- Calendar drops on a day or all-day cell keep the wall-clock time and the absolute duration (DST-safe); time-column drops snap the block's top edge to `snapMinutes`. The override lives until `getRecordSchedule` matches it, and a drop resolving to the same window is ignored. Without `onRecordReschedule` no handle or draggable marker exists (tested).
- A calendar item drags from its whole body like a kanban card, except interactive descendants; `CalendarEventChipOpenTrigger` drags only past 5px (touch: 250ms delay, 5px tolerance). The grip handle, visible only on keyboard focus, is the keyboard and assistive-technology activator.
- `CalendarEventChipOpenTrigger` sits at `z-[1]` inside the `isolate` chip: in `block` the time has `opacity-70` and `order-last`, so without it the time paints over the trigger and swallows the click (#327). `data-calendar-item-action` stays above it with `z-10`; `BlockTimeOpensTheItem` in `Layouts/Calendar/Behavior` clicks the block time.
- `onSelectSlot` fires only for a click that both starts and ends on the bare time-grid column (not on an item, resize edge or the end of a drag), and is ignored while `loading`. The slot is the pointer position floored to `snapMinutes`, one `snapMinutes` long, clamped to the day. Without the prop the column has no handler, no cursor class and no tab stop: the time grid is pointer-only for creation, and the consumer's toolbar action is the keyboard path.
- A full month cell collapses its overflow behind a "+N" `Popover` that lists only the hidden segments, so no item renders twice with the same drag id; an item drags out of the popup like any chip. With `onSelectDay`, the popup's day title is a `PopoverClose` that calls it; without it, the title is plain text.
- In the time grid, a timed item with an `end` gets two pointer-only resize edges (`aria-hidden`, no tab stop) on its top and bottom (top only on the first segment, bottom only on the last). The pointer drags an edge with pointer capture and a live preview that never touches the optimistic override; release goes through the same `onRecordReschedule` commit as a drop. The keyboard path is the move handle, so an item keeps two tab stops like a kanban card: Alt+ArrowUp/ArrowDown moves the start and Shift+ArrowUp/ArrowDown the end, one grid line at a time, announced through `aria-keyshortcuts` and ignored while a drag is active. The moved edge lands on the `snapMinutes` wall-clock grid of `timeZone`, and the item keeps at least `snapMinutes` of duration. Items without `end`, all-day items and month chips do not resize.
- `useDataTable` always registers pagination with `manualPagination: !enablePagination`, so without the flag the table yields every row.
- While `isLoading`, `DataTable` renders `loadingRowCount` skeleton rows shaped by `loadingRowAnatomy`: `lines` (1 or 2) in the first column with an accessor (the selection column has none) and `cell` (`text`, 20px, or `control`, 24px) in the others, so a loading row keeps the height of a loaded one. Pass the page size as `loadingRowCount` when the table paginates.
- With `enableColumnResizing`, `DataTable` switches to `table-fixed` with a `<colgroup>`: every visible column but the last takes `getSize()`, the last has no width and no handle so it absorbs the remaining space, and the table's `minWidth` is `getTotalSize()`, so it fills the container until the sizes overflow it and the container scrolls. Fixed cells clip with `overflow-hidden`. Without the flag the markup keeps the auto layout.
- A `DataTable` column with `meta.aggregations` gets a footer menu (none, count, sum) instead of its `footer`. Aggregates read `getPrePaginatedRowModel()`, so they cover every page, like Notion. Count is the row count; sum skips values that are not finite numbers. Without rows or while loading, aggregated cells render nothing, and a footer with only aggregated columns is left out. The choice is uncontrolled through `defaultAggregations` or controlled through `aggregations`, and a choice the column does not list reads as none.
- With `onRowClick`, each `DataTable` body row gets a `button` in its first cell stretched (`absolute inset-0 -z-10`) against the `tr`, which is `isolate` so the negative `z` stays inside the row. A `button` cannot be a child of `tr`; the negative `z` keeps non-positioned cell controls above it. Cells are `pointer-events-none` and their interactive descendants `pointer-events-auto` (`interactiveDescendants`, shared with `ListRow`), so a plain area reaches the trigger and a checkbox, field or cell button keeps its click. `DataTable` resolves `getRowOpenLabel` into a string for the memoized row, while `onRowClick` reaches it by identity. Without the prop the markup is unchanged (tested). `RowOpensFromAPlainArea` in `Layouts/Data Table/Behavior` asserts this with `elementFromPoint`, since JSDOM has no hit testing.
- `DataTable` wraps the COSS `Table` in `data-slot="data-table"`, the positioned box for two `aria-hidden` fades over the scroll container's edges (issue #127): macOS overlay scrollbars hide while idle and a vertical wheel does not scroll sideways, so the overflow had no cue. `useHorizontalOverflow` reads the viewport through a ref object, not a state callback ref; mount is two commits in the bench because the Base UI `ScrollArea` root measures once after mount.
- Calendar, Gallery, List and Data Table run the consumer's renderer in a memoized leaf below the stateful component: it re-runs only when its identity or inputs change, so a renderer that reads other state with a stable identity goes stale.

Frame:

- `mode="fill"` bounds the frame (`min-h-0 flex-1`) and scrolls the body; it only holds inside a flex column of bounded height, otherwise it grows like `flow`. Data Table, Data Grid and `ListView` are `min-h-0 flex-1` and scroll themselves (the table and grid Base UI `ScrollArea`, the list frame), with a sticky `thead`/`tfoot`, grid header/footer and list group titles, so inside the `fill` body only the rows move; outside a bounded flex column those classes do nothing. `useScrollbarInsets` writes the header and footer heights to `--scrollbar-inset-start`/`--scrollbar-inset-end` on the scroll area and the vertical `ScrollBar` turns them into margins, since Base UI sets its `top` and `bottom` inline; it observes them with `ResizeObserver` and re-subscribes only when the footer appears or goes, never per scroll. The body keeps `overflow-auto` for content beside the layout. `flow` lets the body grow and makes the footer `sticky bottom-0`. Body and footer read the mode from context, not a Tailwind group, so nested frames do not leak.
- `CollectionFrameOverlay` goes inside `CollectionFrameFooter` (`absolute bottom-full`): inside the scrolling body an absolute child would scroll with the records. It centers on the frame, not the viewport, like `DataGridSelectionActions`.

Pagination:

- `CollectionPagination` keeps no page: the consumer passes `page` and `pageCount` and handles `onPageChange`, which receives the target page, never a delta. It clamps: `lastPage` is `max(pageCount, 1)` and the page is clamped into `[1, lastPage]`, so `page={9}` with `pageCount={0}` renders `1 / 1`.
- The `first–last de total` summary renders only when both `total` and `pageSize` are defined, reads `0 de 0` when `total` is 0, and sits in a `p` with `aria-live="polite"`. `label` becomes the `aria-label` of the COSS `Pagination` `nav`; the button labels are fixed pt-BR strings. Its props spread after `data-slot`, so `DataGridPagination` replaces `collection-pagination` with `data-grid-pagination`.

Toolbar:

- `CollectionSearchField` commits on submit and when emptied, never per keystroke. `FilterRadioSubmenu` maps the "all" option to `''`, since a `MenuRadioGroup` cannot represent no choice.
- `FilterRadioSubmenu` with `loading` keeps the "all" option and replaces only `options` with `aria-hidden` skeleton rows, with `aria-busy` on the submenu popup: a `role="menu"` cannot own a `status`, so the rows carry no role of their own.

Data Grid attributes are listed in `layouts/data-grid/AGENTS.md`.

- Variants live in `kanbanCardVariants` and `calendarEventChipVariants`; every class is a complete string so the Tailwind scanner sees it. A condition emits one class through a ternary.

- Time-grid hour labels are `text-[0.625rem]` pending a `--text-2xs` token in the consumer's theme.
