# Get Started

`@tc96/parttens` copies React patterns as source into your workspace, on top of your own COSS components. Install one or more patterns by name:

```bash
npx @tc96/parttens add collection-views properties
```

The Record family has three items: `record-dialog`, `record-preview` and `record-group`.

```bash
npx @tc96/parttens add record-dialog record-preview record-group
```

Preview what would change before writing anything, or compare installed files with the current version:

```bash
npx @tc96/parttens add record-dialog --dry-run
npx @tc96/parttens add record-dialog --diff
```

If the repo blocks `npx`, use `bunx @tc96/parttens add ...` or `pnpm dlx @tc96/parttens add ...`.

Before copying anything, the CLI type-checks the patterns against your own `ui` components. If they do not type-check, it stops with exit code 1, in a `--dry-run` too. Fix the diagnostics it prints, or pass `--force` to install anyway.

## Use

Import from your `patterns` alias:

```tsx
import { CollectionViewOutlet, TextProperty } from '@acme/patterns'
```

## Requirements

- React 19, TypeScript and Tailwind CSS 4
- COSS set up with shadcn, with `components.json` at the monorepo root
- Node and npm to run the CLI. Bun is not required

Whole layouts, such as application shells, install the same way; see [Templates](?path=/docs/templates-doc--doc):

```bash
npx @tc96/parttens add app-shell-1
```

The consumer layout and the aliases the CLI reads are in the root `README.md`.

## How this Storybook is organized

The sidebar follows the layers of your design system, from the smallest parts to whole screens. Each section is named after the alias where its code lives in your workspace, so what you browse here is what you install:

- **UI**: the COSS components the rest is built on, such as Button, Input, Select, Calendar, Chat and Composer. Lives in your `ui` alias.
- **Elements**: parts COSS does not have, made from the base: Text, IconFrame, Avatar. Lives in your `elements` alias.
- **Patterns**: product blocks with behavior: records, properties, collection views, widgets, checklist, wizard, rich text editor. Lives in your `patterns` alias.
- **Application**: installable layouts for a whole app, such as the shells. Lives in your `templates` alias.
- **Templates**: how to install templates, and full reference screens to copy from the Code panel into your app.

Each section only builds on the ones above it: a pattern uses elements and UI, a shell uses patterns, elements and UI.
