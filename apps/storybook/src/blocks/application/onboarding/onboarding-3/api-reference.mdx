# Onboarding3

A dialog onboarding: the same flow inside a `Dialog` with a dot stepper and a success screen. Reach for it to run setup over an existing screen, for example when a person opens a new workspace. Install it with `npx @tc96/parttens add onboarding-3`.

The block keeps no state and never fetches: the current step is controlled with `step` and `onStepChange`, the step forms are the consumer's `content`, and moving on, finishing and skipping are callbacks. The success state is also controlled with `completed`.

The other pages of `Blocks/Application/Onboarding/Onboarding3`: [Playground](?path=/story/blocks-application-onboarding-onboarding3-playground--playground) to try the controls, [States](?path=/story/blocks-application-onboarding-onboarding3-states--default) for default, pending, error and success, [Behavior](?path=/story/blocks-application-onboarding-onboarding3-behavior--shows-current-step-and-counter) for the tests and [Usages](?path=/story/blocks-application-onboarding-onboarding3-usages--complete-setup) for a full flow with TanStack Form.

## Import

```tsx
import { Onboarding3 } from '@tc96/blocks/application/onboarding/onboarding-3'
```

The same path exports the types listed under Exports.

## Anatomy

Three steps on the first one.

<Onboarding3
  onComplete={saveSetup}

  onFinish={goToApp}

## Onboarding3

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `steps` | `OnboardingStep[]` | - | The steps, in order. |
| `step` | `string` | - | The `id` of the current step. An unknown `id` renders no step and disables the moves. |
| `onStepChange` | `(id: string) => void` | - | Called with the `id` of the step to show when Voltar or Continuar moves. |
| `onContinue` | `(stepId: string) => boolean \| undefined` | - | Called before Continuar moves or completes. Returning `false` keeps the step: that is where a step validates. |
| `onComplete` | `() => void` | - | Called by the action of the last step, after `onContinue`. The consumer submits and then sets `completed`. |
| `onSkip` | `(stepId: string) => void` | - | Called by Pular. Without it the action is not rendered. |
| `onFinish` | `() => void` | - | Called by Começar on the success state. |
| `completed` | `boolean` | `false` | Shows the success state in place of the steps. |
| `pending` | `boolean` | `false` | Disables Voltar and Pular and puts Continuar in its loading state. |
| `error` | `string` | - | Shown in an `Alert` above the actions. |
| `open` | `boolean` | - | Whether the dialog is open. |
| `onOpenChange` | `(open: boolean) => void` | - | Called when the dialog asks to open or close (close button, Escape, click outside). |
| `labels` | `Partial<Onboarding3Labels>` | pt-BR texts | Overrides the texts of the block; see Labels below. |
| `className` | `string` | - | Merged into the root classes. |

## OnboardingStep

| Field | Type | Description |
| --- | --- | --- |
| `id` | `string` | Identifies the step and is passed to the callbacks. |
| `title` | `string` | The step heading. |
| `description` | `string` | Optional line under the title. |
| `content` | `ReactNode` | The step body, usually a form. |

## Accessibility and theme

- The dialog is named by the current step title, or by `labels.successTitle` on the success state.
- The dots are a list named by `labels.steps`; the current one has `aria-current="step"` and each carries the step title as hidden text.
- Focus and Escape come from the COSS `Dialog`; an `error` renders in an `Alert`, which has `role="alert"`.
- The block carries no raw color, radius or shadow: it uses COSS components `Dialog`, `Button` and `Alert`.
