# SettingsCatalog7

A settings section for the reasons a seller picks when a lead is lost. It has a switch that requires a reason, a switch that allows a custom reason, and a list of reasons with how many leads each one lost. Each reason row has a menu to edit, archive or delete when the app handles actions, and archived reasons sit in a collapsible that starts closed. Reach for it when the app asks people why they lost a lead. Install it with `npx @tc96/cli add settings-catalog-7`.

It is a section, not a page: it renders no `main` landmark. Creating, editing, archiving and deleting stay in the app; the block only calls its callbacks, keeps no list of its own and never fetches or stores anything.

The other pages of `Blocks/Application/Settings/Catalog/Settings7`: [Playground](?path=/story/blocks-application-settings-catalog-settings7-playground--playground) to try the texts, the empty list, the archived reasons and the actions, [Behavior](?path=/story/blocks-application-settings-catalog-settings7-behavior--require-reason-switch-calls-on-require-reason-change) for the tests and [Usages](?path=/story/blocks-application-settings-catalog-settings7-usages--loaded) for the list read over the network.

## SettingsCatalog7

The loss reasons section. Renders the lost leads section with its two switches, then the reasons section with the title, the description and, with `onCreate`, the New reason button. Each reason is a row; with no reasons it renders an empty state in place of the rows. The archived collapsible renders only when `archivedReasons` has items.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `reasons` | `SettingsCatalog7Reason[]` | required | The reasons to list; an empty array shows the empty state. |
| `archivedReasons` | `SettingsCatalog7Reason[]` | `[]` | Reasons listed in a collapsible that starts closed. Without items the collapsible is not rendered. |
| `requireReason` | `boolean` | `false` | The state of the required reason switch. |
| `onRequireReasonChange` | `(checked: boolean) => void` | - | Called with the new value when the required reason switch is toggled. |
| `allowCustomReason` | `boolean` | `true` | The state of the custom reason switch. |
| `onAllowCustomReasonChange` | `(checked: boolean) => void` | - | Called with the new value when the custom reason switch is toggled. |
| `onCreate` | `() => void` | - | Called when the New reason button is clicked. Without it the button is not rendered. |
| `onReasonAction` | `(reasonId: string, action: SettingsCatalog7Action) => void` | - | Called with the reason id and the chosen action when a menu item is chosen. Without it the row menus are not rendered. |
| `pending` | `boolean` | `false` | Replaces the content with the skeleton of the block, an `output` with `aria-busy="true"` named by `labels.loading`. Wins over `error`. |
| `error` | `boolean` | `false` | Replaces the content with the error `StateSurface` (`role="alert"`). Wins over the empty state. |
| `onRetry` | `() => void` | - | Called by the Tentar novamente button of the error state; without it the button does not render. |
| `labels` | `Partial<SettingsCatalog7Labels>` | pt-BR texts | Overrides the texts of the block; see Labels below. |
| `className` | `string` | - | Merged into the root's classes. |

## Accessibility and theme

- The two switches are named by `labels.requireReason` and `labels.allowCustomReason`.
- The row menu button is named by `labels.actions(name)`, so each row's menu is told apart by screen readers.
- The archived collapsible is a button labelled by `labels.archived` and starts closed.
- The empty state has `role="status"` and `data-kind="empty"`.
- The block carries no color, radius or shadow of its own: the theme belongs to the app.
