# Settings19

A settings section that lists webhook endpoints. Each row shows the URL, how many events it receives and when the last delivery happened, with an enable switch and, when the app handles actions, a menu. When any endpoint is failing, an alert above the section tells it. Reach for it when the app delivers events to URLs the customer controls. Install it with `npx @tc96/cli add settings-19`.

It is a section, not a page: it renders no `main` landmark. Creating, testing, editing and deleting stay in the app; the block keeps no list of its own and never fetches or stores anything.

The other pages of `Blocks/Application/Settings/Settings19`: [Playground](?path=/story/blocks-application-settings-settings19-playground--playground) to try the texts, the health alert and the empty list, [Behavior](?path=/story/blocks-application-settings-settings19-behavior--failing-endpoint-shows-health-alert) for the tests and [Usages](?path=/story/blocks-application-settings-settings19-usages--loaded) for the endpoints read over the network.

## Import

```tsx
import { Settings19 } from '@tc96/ui/blocks/application/settings/settings-19'
```

The same path exports the types `Settings19Props`, `Settings19Endpoint`, `Settings19Action` and `Settings19Labels`.

## Anatomy

The section with one failing endpoint and one disabled endpoint:

<Canvas of={ApiReferenceStories.Anatomy} />

```tsx
<Settings19
  endpoints={endpoints}
  onCreate={openNewEndpoint}
  onEnabledChange={(id, enabled) => save(id, enabled)}
  onEndpointAction={(id, action) => handleAction(id, action)}
/>
```

## Settings19

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `endpoints` | `Settings19Endpoint[]` | required | The endpoints to list; an empty array shows the empty state. |
| `onEnabledChange` | `(endpointId: string, enabled: boolean) => void` | - | Called when the enable switch of a row is toggled. |
| `onCreate` | `() => void` | - | Called when the New endpoint button is clicked. Without it the button is not rendered. |
| `onEndpointAction` | `(endpointId: string, action: Settings19Action) => void` | - | Called with the id and `'edit'`, `'send-test'` or `'delete'` when a menu item is chosen. Without it the row menus are not rendered. |
| `pending` | `boolean` | `false` | Replaces the content with the skeleton of the block, an `output` with `aria-busy="true"` named by `labels.loading`. Wins over `error`. |
| `error` | `boolean` | `false` | Replaces the content with the error `StateSurface` (`role="alert"`). Wins over the empty state. |
| `onRetry` | `() => void` | - | Called by the Tentar novamente button of the error state; without it the button does not render. |
| `labels` | `Partial<Settings19Labels>` | pt-BR texts | Overrides the texts of the block; see Labels below. |
| `className` | `string` | - | Merged into the wrapper of the alert and the section. |

## Settings19Endpoint

| Field | Type | Description |
| --- | --- | --- |
| `id` | `string` | Identifies the endpoint in the callbacks. |
| `url` | `string` | Title of the row and part of the accessible names. |
| `enabled` | `boolean` | Value of the enable switch. |
| `events` | `number` | Event types the endpoint receives, shown by `labels.eventCount`. |
| `lastDelivery` | `string` | Final text of the last delivery, such as `"há 3 minutos"`, passed to `labels.lastDelivery`. |
| `failing` | `boolean` | Shows the Falhando badge; when any endpoint is failing the health alert renders. |

## Accessibility and theme

- The health alert has `role="alert"`; it renders only while an endpoint is failing.
- Each switch and each row menu are named by the endpoint URL.
- The empty state has `role="status"` and `data-kind="empty"`.
- The block carries no color, radius or shadow of its own: the theme belongs to the app.
