# Settings10

A settings section that lists the stages of a funnel, grouped by phase. Each stage shows its icon, its name, how many leads it holds and, for a phase that closes the deal, how it closes. When the app handles actions, each stage has a menu to edit, move it up or down within its phase, or delete it. Reach for it when the app lets people organize the steps a lead goes through. Install it with `npx @tc96/parttens add settings-10`.

It is a page section: it renders a `main` landmark with the section inside. Creating, editing, moving and deleting stay in the app; the block only calls `onStageCreate` and `onStageAction`, keeps the list of stages in the props and never fetches or stores anything. Its only state is the open state of the New stage dialog.

The other pages of `Blocks/Application/Settings/Settings10`: [Playground](?path=/story/blocks-application-settings-settings10-playground--playground) to try the texts and the actions, [Behavior](?path=/story/blocks-application-settings-settings10-behavior--stage-description-shows-leads-and-closing) for the tests and [Usages](?path=/story/blocks-application-settings-settings10-usages--loaded) for the stages read over the network, moved and created in place.

## Import

```tsx
import { Settings10 } from '@tc96/blocks/application/settings/settings-10'
```

The same path exports the types `Settings10Props`, `Settings10Stage`, `Settings10Phase`, `Settings10Action` and `Settings10Labels`.

The section with its phases, each with its stages:

## Settings10

The stages section. Renders the title, the description and, with `onStageCreate`, the New stage button and its dialog, then one group per phase, in the order of `phases`, each listing its stages in the order of `stages`. A stage with `locked` has only the Edit action in its menu.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `phases` | `Settings10Phase[]` | required | The phases, one group each, in order. |
| `stages` | `Settings10Stage[]` | required | The stages; each one is listed in the group of its `phase`. |
| `onStageCreate` | `(name: string, phaseId: string) => void` | - | Called with the trimmed name and the chosen phase when the dialog is submitted. Without it the New stage button is not rendered. |
| `onStageAction` | `(stageId: string, action: Settings10Action) => void` | - | Called with the stage id and `'edit'`, `'move-up'`, `'move-down'` or `'delete'` when a menu item is chosen. Without it the stage menus are not rendered. |
| `pending` | `boolean` | `false` | Replaces the content with the skeleton of the block, an `output` with `aria-busy="true"` named by `labels.loading`. Wins over `error`. |
| `error` | `boolean` | `false` | Replaces the content with the error `StateSurface` (`role="alert"`). Wins over the empty state. |
| `onRetry` | `() => void` | - | Called by the Tentar novamente button of the error state; without it the button does not render. |
| `labels` | `Partial<Settings10Labels>` | pt-BR texts | Overrides the texts of the block; see Labels below. |
| `className` | `string` | - | Merged into the section's classes. |

The block takes no other props.

## Settings10Phase

| Field | Type | Description |
| --- | --- | --- |
| `id` | `string` | Identifies the phase; a stage's `phase` points to it, and the dialog reports it. |
| `label` | `string` | The title of the phase group, and the phase name in the closing text. |
| `closed` | `boolean` | Marks a phase that closes the deal. Its stages without a lead count read `Fecha como` followed by the label in lower case. |

## Settings10Stage

| Field | Type | Description |
| --- | --- | --- |
| `id` | `string` | Identifies the stage in `onStageAction`. |
| `name` | `string` | Title of the row. |
| `icon` | `Icon` (Phosphor) | Drawn before the name. |
| `tone` | `string` | Classes of the icon, for example `text-blue-700 dark:text-blue-500`. |
| `phase` | `string` | The `id` of the phase that holds the stage. |
| `leads` | `number` | Leads in the stage, shown in `labels.stageDescription`. |
| `locked` | `boolean` | Removes Move up, Move down and Delete from the menu; the stage keeps Edit. |

## Accessibility and theme

- Each phase is a named region, with the phase label as its name.
- The stage menu button is named by `labels.actions(name)`, so each stage's menu is told apart by screen readers.
- The New stage dialog disables its submit button while the name is empty or already used by another stage, ignoring case.
- The block carries no color, radius or shadow of its own: the theme belongs to the app.
