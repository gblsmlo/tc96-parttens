# Settings1

A profile and account section: an avatar, the editable fields, the e-mail with its own save button, the sessions count and the account actions. Reach for it when the app lets people edit their own profile and account. Install it with `npx @tc96/parttens add settings-1`.

It is a section, not a page: it renders no `main` landmark. Saving the fields, uploading the avatar, signing out and deleting the account stay in the app; the block only calls the handlers and never fetches or stores anything. The e-mail form validates the address itself and clears its error on the next valid submit.

The other pages of `Blocks/Application/Settings/Settings1`: [Playground](?path=/story/blocks-application-settings-settings1-playground--playground) to try the texts, the sessions count and the actions, [Behavior](?path=/story/blocks-application-settings-settings1-behavior--email-submit-calls-on-email-submit) for the tests and [Usages](?path=/story/blocks-application-settings-settings1-usages--loaded) for the account read over the network.

## Import

```tsx
import { Settings1 } from '@tc96/blocks/application/settings/settings-1'
```

The same path exports the types `Settings1Field`, `Settings1Labels` and `Settings1Props`.

## Settings1

The profile and account sections. Renders the avatar row, one row per field, the e-mail form, the sessions row and the delete row. The avatar button and the e-mail form are always rendered; the sign-out and delete buttons appear only with their callbacks.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `avatarInitials` | `string` | required | Initials shown in the avatar button. |
| `email` | `string` | required | Starting value of the e-mail field. The form keeps its own value after that. |
| `fields` | `Settings1Field[]` | required | The editable rows of the profile section, in order. |
| `sessionCount` | `number` | required | Count shown in the sessions row, in the singular or the plural. |
| `pending` | `boolean` | `false` | Replaces the content with the skeleton of the block, an `output` with `aria-busy="true"` named by `labels.loading`. Wins over `error`. |
| `error` | `boolean` | `false` | Replaces the content with the error `StateSurface` (`role="alert"`). Wins over the empty state. |
| `onRetry` | `() => void` | - | Called by the Tentar novamente button of the error state; without it the button does not render. |
| `labels` | `Partial<Settings1Labels>` | pt-BR texts | Overrides the texts of the block; see Labels below. |
| `onDeleteAccount` | `() => void` | - | Called when the delete button is clicked. Without it the button is not rendered. |
| `onEmailSubmit` | `(email: string) => void` | - | Called with the trimmed e-mail when the save button is clicked and the address is valid. |
| `onFieldCommit` | `(fieldId: string, value: string) => void` | - | Called with the field id and its value when a field loses focus. |
| `onSignOutEverywhere` | `() => void` | - | Called when the sign-out button is clicked. Without it the button is not rendered. |
| `onUploadAvatar` | `() => void` | - | Called when the avatar button is clicked. |
| `className` | `string` | - | Merged into the root element's classes. |

## Accessibility and theme

- The avatar is a button named by `labels.uploadAvatar`; its initials are its fallback text.
- Each field input is named by its `label`, and the e-mail input by `labels.emailLabel`.
- A rejected e-mail shows its error under the input through the field's error text.
- The block carries no color, radius or shadow of its own: the theme belongs to the app.
