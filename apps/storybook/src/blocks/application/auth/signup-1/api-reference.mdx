# Signup1

A sign-up page: name, e-mail, a password with live feedback and a confirmation, both with a show and hide button, optional providers, a terms notice that is only links and a sign in link, inside a centered card. Reach for it as the route of an app's account creation screen, or as the page to edit into your own. Install it with `npx @tc96/parttens add signup-1`.

It is a whole page, not a form to place inside one: it renders its own `main` landmark. Account creation, the session, cookies and redirects stay in the app; the block only calls `onSubmit` and `onProviderSelect`, and it never fetches or stores anything.

The other pages of `Blocks/Application/Auth/Signup1`: [Playground](?path=/story/blocks-application-auth-signup1-playground--playground) to try the errors, the pending state, the password rules and the optional parts, [Stories](?path=/story/blocks-application-auth-signup1-stories--default) for the pending, error, field error and password rule states, [Behavior](?path=/story/blocks-application-auth-signup1-behavior--page-heading) for the tests, [Usages](?path=/story/blocks-application-auth-signup1-usages--create-account) for real sign-up screens and [Layouts](?path=/story/blocks-application-auth-signup1-layouts--minimal) for the page without its optional parts.

## Import

```tsx
import { Signup1 } from '@acme/blocks/application/auth/signup-1'
```

The same path exports the types `SignupProps`, `SignupValues`, `SignupLabels`, `AuthProvider`, `AuthPasswordSuggestion`, `AuthRenderLink`, `AuthBaseProps`, `AuthCommonLabels`, `AuthNewPasswordLabels` and `AuthFieldErrors`.

The page with a form `error`, the providers, the terms notice and the sign in link:

## Signup1

The whole sign-up page. Renders a `main` that fills the window height and centers its content, the optional `logo` above a card, and inside it the title (an `h1`), the description, the form message, the form, the optional providers, the terms notice and the footer. Mount it on the route and do not wrap it in another `main`. It only takes the props below.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `onSubmit` | `(values: SignupValues) => void` | required | Called with `name`, `email` and `password` after the constraints and the confirmation pass; never while `pending`. |
| `passwordMinLength` | `number` | `8` | Sets the native `minLength` of the password and the number in the length feedback. |
| `passwordSuggestions` | `AuthPasswordSuggestion[]` | `["lowercase", "uppercase", "number", "symbol"]` | Lists the character types the feedback suggests; an empty list hides them. |
| `pending` | `boolean` | `false` | When true, disables the submit button and the provider buttons, shows `labels.submitPending` and sets `aria-busy` on the form. |
| `error` | `string` | - | Shows a message for the whole form in an alert titled `labels.errorTitle`. |
| `fieldErrors` | `Partial<Record<keyof SignupValues, string>>` | - | Shows a message under each field it names (`name`, `email` or `password`) and marks that field invalid. |
| `providers` | `AuthProvider[]` | - | Lists the provider buttons below the form; empty or missing renders neither the buttons nor their separator. |
| `onProviderSelect` | `(id: string) => void` | - | Called with the `id` of the provider button clicked; never while `pending`. |
| `termsHref` | `string` | - | Renders the terms link of the terms notice when set. |
| `privacyHref` | `string` | - | Renders the privacy link of the terms notice when set. |
| `loginHref` | `string` | - | Renders the sign in link in the footer when set; without it the footer is not rendered. |
| `renderLink` | `(href: string) => ReactElement` | `renderAnchor` | Returns the element each link renders as, so the app's router owns navigation. |
| `logo` | `ReactNode` | - | Renders above the card, outside it, centered. |
| `labels` | `Partial<SignupLabels>` | - | Overrides the texts the block owns; each missing key keeps its pt-BR default. |

| Attribute | Values | Description |
| --- | --- | --- |
| `data-slot` | `"card"` | Marks the card, which holds everything but the `logo` |
| `data-slot` | `"form"` | Marks the form; it carries `aria-busy` |
| `data-slot` | `"field-description"` | Marks the password feedback: the length and the suggestions |
| `data-met` | present when met | On the `li` of a suggestion the password already satisfies |

### Submit

`onSubmit` runs when the form is submitted by the button or by Enter. It runs only after the native constraints pass (`required` on every field, `type="email"` on the e-mail and `minLength` on the password), only when the password and the confirmation match, and never while `pending`. The password confirmation and the terms notice add nothing to the values. The return value is ignored. The fields are uncontrolled, so what the user typed stays in the form after an error. The messages of the native constraints are the browser's own and have no label.

### Confirmation

After the native constraints, the block checks that both password fields are equal. When they differ it shows `labels.passwordMismatch` under the confirmation, marks it `aria-invalid`, moves focus to it and does not call `onSubmit`. The message clears when either password field is edited. The confirmation is not a key of `SignupValues`, so `fieldErrors` cannot target it, and its value never leaves the block.

### Password feedback

Under the password field, the block shows the length as `labels.passwordLength(count, passwordMinLength)` and, below it, `labels.passwordSuggestionsTitle` with one item per entry of `passwordSuggestions`. Each item reads its state in text, `labels.suggestionMet` or `labels.suggestionMissing`, so the state never relies on the icon or the color alone. The feedback is advice: only `passwordMinLength` blocks the submit. It describes the password field through `aria-describedby`, and a polite live region announces only when the minimum is reached or lost, or when a suggestion changes state, not on every key.

Values of `AuthPasswordSuggestion`: `"lowercase"`, `"uppercase"`, `"number"` and `"symbol"`.

### Terms notice

Plain text with links, below the providers: `labels.termsLead`, then a link for each of `termsHref` and `privacyHref` that is passed, joined by `labels.termsAnd`. There is no checkbox and nothing is added to the values. With neither `href` the notice is not rendered. With only `privacyHref` the default `termsLead` ("... com os") reads wrong in pt-BR, so override `labels.termsLead` then.

### Errors

- `error` is rendered as text, never as HTML. When it goes from empty to a message, focus moves to the alert, unless `fieldErrors` names a field, which takes the focus.
- `fieldErrors` ties each message to its field with `aria-invalid` and the field's error text. When it goes from empty to filled, focus moves to the first of those fields in the form. A message clears when the user edits its field.
- Both are the app's state: the block never sets either of them.

### Links

Every link renders through `renderLink(href)`, and only when its `href` is passed: `loginHref`, `termsHref` and `privacyHref`. The element receives the class names and the text through its props, so it needs no children; the default is a plain `a`.

### AuthProvider

One entry of `providers`. Each renders an outline button named by `labels.providerContinue(label)`, inside a group named by `labels.providersGroup`.

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `id` | `string` | required | Identifies the provider; `onProviderSelect` receives it. |
| `label` | `string` | required | Names the provider in the button text. |
| `icon` | `ReactNode` | - | Renders before the text of the button. |

### SignupValues

The argument of `onSubmit`.

| Field | Type | Description |
| --- | --- | --- |
| `name` | `string` | The name field. |
| `email` | `string` | The e-mail field. |
| `password` | `string` | The password field. |

## Accessibility and theme

- The page has one `main` landmark and one `h1`, the card title; do not wrap the block in another `main`.
- Both password buttons are named by `labels.showPassword` and `labels.hidePassword`; override both when you translate the block.
- The block carries no theme rule: it reads the card, field, button and alert tokens of the theme it renders in.
