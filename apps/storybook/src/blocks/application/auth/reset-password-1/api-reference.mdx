# ResetPassword1

The page where a user sets a new password after following the link in an e-mail: a new password with live feedback and a confirmation, each with a show and hide button, and a link back to sign in, in a centered card. The reset token never passes through the block: the app reads it from the route and sends it with the new password. The block is a whole page that mounts on the route and only calls `onSubmit`.

The other pages of `Blocks/Application/Auth/ResetPassword/ResetPassword1`: [Playground](?path=/story/blocks-auth-resetpassword-resetpassword1-playground--playground) to try the texts, the form message, the password rules and the optional parts, [Stories](?path=/story/blocks-auth-resetpassword-resetpassword1-stories--default) for the error, field error and pending states, [Behavior](?path=/story/blocks-auth-resetpassword-resetpassword1-behavior--title-is-level-one-heading) for the tests, [Usages](?path=/story/blocks-auth-resetpassword-resetpassword1-usages--reset-from-email-link) for real cases and [Layouts](?path=/story/blocks-auth-resetpassword-resetpassword1-layouts--minimal) for the page without its optional parts.

The auth blocks share one contract: `pending`, `error`, `fieldErrors`, `renderLink`, `labels`, `logo` and the page frame work the same way in each of them, and each block's page describes them for itself.

## Import

Install it with `npx @tc96/parttens add reset-password-1`, then import it from the `blocks` alias of the app:

```tsx
import { ResetPassword1 } from '@acme/blocks/application/auth/reset-password-1'
```

```tsx
        <div data-slot="field">
          <label data-slot="field-label">{labels.newPassword}</label>
          <input name="password" type="password" />
          <button type="button">{labels.showPassword}</button>
          <div data-slot="field-error" />
          <div data-slot="field-description">{feedback}</div>
          <div aria-live="polite" />
        </div>
        <div data-slot="field">
          <label data-slot="field-label">{labels.confirmPassword}</label>
          <input name="confirmPassword" type="password" />
          <button type="button">{labels.showPassword}</button>
          <div data-slot="field-error" />
        </div>
        <button type="submit">{labels.submit}</button>
      </form>
    </div>
  </div>
  <div data-slot="auth-footer">

  </div>

```

The `logo` wrapper renders only with `logo`, the `alert` only with `error`, and the `auth-footer` only with `loginHref`.

## ResetPassword1

The reset password page. Renders a `main` landmark that centers its content in the window height, a `Card` with the optional `logo` above the title (an `h1`), the description, the form message, the form and the footer. Mount it on the route and do not wrap it in another `main`. The password change, the session and the redirect after it stay in the app.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `onSubmit` | `(values: ResetPasswordValues) => void` | required | Called with `{ password }` after the native constraints pass and both passwords match; the return value is ignored. |
| `pending` | `boolean` | `false` | When true, disables the submit button, puts the submit button in its `loading` state, sets `aria-busy` on the form and stops `onSubmit`, Enter included. |
| `error` | `string` | - | Sets a message for the whole form, shown in an `Alert` with the title `labels.errorTitle`; rendered as text, never as HTML. |
| `fieldErrors` | `{ password?: string }` | - | Sets a message for the new password field, shown under it and tied to it with `aria-invalid`. |
| `passwordMinLength` | `number` | `8` | Sets the native `minLength` of the new password. |
| `passwordSuggestions` | `AuthPasswordSuggestion[]` | `"lowercase"`, `"uppercase"`, `"number"` and `"symbol"` | Lists the character types the feedback suggests; an empty list hides them. |
| `loginHref` | `string` | - | Adds the footer link back to sign in, named by `labels.backToLogin`; without it the footer is not rendered. |
| `logo` | `ReactNode` | - | Renders inside the card, centered above the title; nothing renders in its place when missing. |
| `renderLink` | `(href: string) => ReactElement` | a plain `a` | Renders every link of the page, so the router of the app owns navigation (`(href) => <Link to={href} />`). |
| `labels` | `Partial<ResetPasswordLabels>` | pt-BR texts | Overrides the texts of the block; see Labels below. |

The block takes no other props.

Values of `AuthPasswordSuggestion`: `"lowercase"`, `"uppercase"`, `"number"` and `"symbol"`.

| Attribute | Values | Description |
| --- | --- | --- |
| `data-met` | present when the suggestion is met | Set on the `li` of a suggestion that the typed password already satisfies; lets the consumer style the met state |
| `aria-busy` | `"true"` or `"false"` | Set on the form from `pending` |

## Password and confirmation

The first field is `password` (the label `labels.newPassword`) and the second is `confirmPassword`; both are required, take `autocomplete="new-password"` and have a button that shows or hides the typed value without changing it or submitting. Only `password` has `minLength`.

On submit, after the native constraints, the block checks that both passwords are equal. When they differ it shows `labels.passwordMismatch` in the confirmation field, marks it `aria-invalid`, moves focus to it and does not call `onSubmit`. The message clears when either field is edited. The confirmation is not a key of `ResetPasswordValues`, so `fieldErrors` cannot target it and its value never leaves the block.

Under the new password field the feedback shows the suggested character types, inline on one line, with a check in the `success` color once met (the state is also read by screen readers through `labels.suggestionMet` or `labels.suggestionMissing`). The feedback is advice: only the native constraints block the submit. It is tied to the field by `aria-describedby`, and a polite live region announces only when a suggestion changes state, not on every key. The fields are uncontrolled: the values stay in the form after an error.

## Errors and focus

`error` and `fieldErrors` come from the app after it handles the submit. When `fieldErrors.password` goes from empty to filled, focus moves to the new password field. When `error` goes from empty to filled and no field is invalid, focus moves to the `Alert`. Nothing takes focus on mount, and a field message clears when the user edits its field. The native constraint messages (`required`, `minLength`) are the browser's own and have no label.

An expired or invalid reset token comes back through `error`, for example "The link expired. Ask for a new one.".

## The reset token

There is no token prop, no token field and no token in `ResetPasswordValues`. The app reads the token from the route and sends it with the new password; the block neither reads, validates nor keeps it.

## Links

The back to sign in link renders only when `loginHref` is passed, through `renderLink(loginHref)`. Without `renderLink` it is a plain `a`.

## Accessibility and theme

- The page renders its own `main` landmark and one `h1`, the title; a consumer that wraps it in another `main` ends up with two.
- Pass a `logo` that carries its own text or `aria-label`; the block adds none.
- The password toggles take their names from `labels.showPassword` and `labels.hidePassword`; translate both with the rest of the labels.
- The block carries no color, radius or shadow of its own: the theme belongs to the app.
