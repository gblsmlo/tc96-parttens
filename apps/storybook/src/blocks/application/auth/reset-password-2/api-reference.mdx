# ResetPassword2

The page where a user sets a new password after following the link in an e-mail, when that link is valid for a limited time and the app shows how long is left: the time above the form, and an expired state with a request for a new link when it runs out. It is `ResetPassword1` plus a timer that the app controls: a new password with live feedback and a confirmation, each with a show and hide button, and a link back to sign in, in a centered card. Without `expiresIn` it behaves exactly like `ResetPassword1`. The block runs no timer and no clock, and the reset token never passes through it.

The other pages of `Blocks/Application/Auth/ResetPassword/ResetPassword2`: [Playground](?path=/story/blocks-application-auth-resetpassword-resetpassword2-playground--playground) to try the texts, the timer, the form message and the optional parts, [Stories](?path=/story/blocks-application-auth-resetpassword-resetpassword2-stories--default) for the expired, error, field error and pending states, [Behavior](?path=/story/blocks-application-auth-resetpassword-resetpassword2-behavior--title-is-level-one-heading) for the tests, [Usages](?path=/story/blocks-application-auth-resetpassword-resetpassword2-usages--reset-from-email-link) for real cases and [Layouts](?path=/story/blocks-application-auth-resetpassword-resetpassword2-layouts--minimal) for the page without its optional parts.

The auth blocks share one contract: `pending`, `error`, `fieldErrors`, `renderLink`, `labels`, `logo` and the page frame work the same way in each of them, and each block's page describes them for itself.

## Import

Install it with `npx @tc96/parttens add reset-password-2`, then import it from the `blocks` alias of the app:

```tsx
import { ResetPassword2 } from '@acme/blocks/application/auth/reset-password-2'
```

## Anatomy

<ResetPassword2

  logo={<Logo />}

The tree it renders while the link is valid, with the `data-slot` of each part:

```tsx
<main>
  <div data-slot="card">
    <div data-slot="card-header">
      <div>{logo}</div>
      <h1 data-slot="card-title">{labels.title}</h1>
      <div data-slot="card-description">{labels.description}</div>
    </div>
    <div data-slot="card-panel">
      <div data-slot="alert" role="alert">{error}</div>
      <p>{labels.linkExpiresIn(time)}</p>
      <span aria-live="polite">{labels.expiringSoon}</span>
      <form data-slot="form" aria-busy={pending}>
        <div data-slot="field">
          <label data-slot="field-label">{labels.newPassword}</label>
          <input name="password" type="password" />
          <button type="button">{labels.showPassword}</button>
          <div data-slot="field-error" />
          <div data-slot="field-description">{feedback}</div>
          <div aria-live="polite" />
        </div>
        <div data-slot="field">
          <label data-slot="field-label">{labels.confirmPassword}</label>
          <input name="confirmPassword" type="password" />
          <button type="button">{labels.showPassword}</button>
          <div data-slot="field-error" />
        </div>
        <button type="submit">{labels.submit}</button>
      </form>
    </div>
  </div>
  <div data-slot="auth-footer">
    <a href={loginHref}>{labels.backToLogin}</a>
  </div>
</main>
```

The `logo` wrapper renders only with `logo`, the `alert` only with `error`, the `p` and the live `span` only with `expiresIn`, and the `auth-footer` only with `loginHref`. The `span` is empty until `expiresIn` reaches one minute.

When the link has expired the form is replaced, inside the same `main` and card:

```tsx
<div data-slot="card">
  <div data-slot="card-header">
    <h1 data-slot="card-title" tabIndex={-1}>{labels.expiredTitle}</h1>
    <div data-slot="card-description">{labels.expiredDescription}</div>
  </div>
  <div data-slot="card-panel">
    <div data-slot="alert" role="alert">{error}</div>
    <button type="button">{labels.requestNewLink}</button>
  </div>
  <div data-slot="card-footer">
    <a href={loginHref}>{labels.backToLogin}</a>
  </div>
</div>
```

## ResetPassword2

The reset password page with a validity timer. Renders a `main` landmark that centers its content in the window height, a `Card` with the optional `logo` above the title (an `h1`), the description, the form message, the form or the expired state, and the footer. Mount it on the route and do not wrap it in another `main`. The password change, the new link request, the session and the redirect after them stay in the app.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `onSubmit` | `(values: ResetPassword2Values) => void` | required | Called with `{ password }` after the native constraints pass and both passwords match; never while `pending` and never in the expired state, where there is no form. |
| `expiresIn` | `number` | - | Sets the seconds left on the link; the app counts it down and passes the new value on every tick. Missing means no timer and no expired state. |
| `requestNewLinkIn` | `number` | `0` | Sets the seconds left before another request is allowed, counted by the app like `expiresIn`; above zero it disables the request button. |
| `onRequestNewLink` | `() => void` | - | Called when the request button of the expired state is clicked; the button renders only when this is passed. |
| `pending` | `boolean` | `false` | When true, disables the submit button and the request button, puts the submit button in its `loading` state, sets `aria-busy` on the form and stops `onSubmit` and `onRequestNewLink`. |
| `error` | `string` | - | Sets a message for the whole form, shown in an `Alert` with the title `labels.errorTitle`, in the form and in the expired state; rendered as text, never as HTML. |
| `fieldErrors` | `{ password?: string }` | - | Sets a message for the new password field, shown under it and tied to it with `aria-invalid`. |
| `passwordMinLength` | `number` | `8` | Sets the native `minLength` of the new password. |
| `passwordSuggestions` | `AuthPasswordSuggestion[]` | `"lowercase"`, `"uppercase"`, `"number"` and `"symbol"` | Lists the character types the feedback suggests; an empty list hides them. |
| `loginHref` | `string` | - | Adds the footer link back to sign in, named by `labels.backToLogin`, in the form and in the expired state; without it the footer is not rendered. |
| `logo` | `ReactNode` | - | Renders inside the card, centered above the title; nothing renders in its place when missing. |
| `renderLink` | `(href: string) => ReactElement` | a plain `a` | Renders every link of the page, so the router of the app owns navigation (`(href) => <Link to={href} />`). |
| `labels` | `Partial<ResetPassword2Labels>` | pt-BR texts | Overrides the texts of the block; see Labels below. |

The block takes no other props.

Values of `AuthPasswordSuggestion`: `"lowercase"`, `"uppercase"`, `"number"` and `"symbol"`.

| Attribute | Values | Description |
| --- | --- | --- |
| `data-met` | present when the suggestion is met | Set on the `li` of a suggestion that the typed password already satisfies; lets the consumer style the met state |
| `aria-busy` | `"true"` or `"false"` | Set on the form from `pending` |

## The timer

The app owns the clock. It reads the deadline of the link, counts the seconds left and passes them in `expiresIn` on every tick; the block runs no interval, no timeout and no clock of its own.

While `expiresIn` is above zero, the block shows `labels.linkExpiresIn` with the time as `m:ss` (581 is `9:41`) above the form. Fractions are floored. The time is plain text outside any `aria-live` region, so a screen reader does not read it every second. The only live region is a visually hidden one that holds `labels.expiringSoon` once `expiresIn` is 60 or less, derived from the prop with no state.

When `expiresIn` is zero or less the form is replaced, inside the same card, by the expired state: the title `labels.expiredTitle` (an `h1`), `labels.expiredDescription`, the request button when `onRequestNewLink` is passed, and the back to sign in link when `loginHref` is passed. `onSubmit` cannot be called from there. Focus moves to the expired title, which has `tabindex="-1"`, only when `expiresIn` goes from above zero to zero or less; a page that mounts already expired does not take focus. If `expiresIn` rises above zero again, the form returns.

## The request for a new link

The request button renders only in the expired state and only when `onRequestNewLink` is passed. It is disabled while `requestNewLinkIn` is above zero, and then reads `labels.requestNewLinkIn` with the time as `m:ss` as plain text outside any `aria-live` region; at zero or when `requestNewLinkIn` is missing it reads `labels.requestNewLink` and is enabled. It is also disabled while `pending`, and the callback is guarded in both cases. What a new request does (send an e-mail, restart the timers) stays in the app.

## Password and confirmation

The first field is `password` (the label `labels.newPassword`) and the second is `confirmPassword`; both are required, take `autocomplete="new-password"` and have a button that shows or hides the typed value without changing it or submitting. Only `password` has `minLength`.

On submit, after the native constraints, the block checks that both passwords are equal. When they differ it shows `labels.passwordMismatch` in the confirmation field, marks it `aria-invalid`, moves focus to it and does not call `onSubmit`. The message clears when either field is edited. The confirmation is not a key of `ResetPassword2Values`, so `fieldErrors` cannot target it and its value never leaves the block.

Under the new password field the feedback shows the suggested character types, inline on one line, with a check in the `success` color once met (the state is also read by screen readers through `labels.suggestionMet` or `labels.suggestionMissing`). The feedback is advice: only the native constraints block the submit. It is tied to the field by `aria-describedby`, and a polite live region announces only when a suggestion changes state, not on every key. The fields are uncontrolled: the values stay in the form after an error.

## Errors and focus

`error` and `fieldErrors` come from the app after it handles the submit or the request. When `fieldErrors.password` goes from empty to filled, focus moves to the new password field. When `error` goes from empty to filled and no field is invalid, focus moves to the `Alert`. Nothing takes focus on mount, and a field message clears when the user edits its field. The native constraint messages (`required`, `minLength`) are the browser's own and have no label.

## The reset token

There is no token prop, no token field and no token in `ResetPassword2Values`. The app reads the token from the route and sends it with the new password; the block neither reads, validates nor keeps it.

## Links

The back to sign in link renders only when `loginHref` is passed, through `renderLink(loginHref)`, in the form and in the expired state. Without `renderLink` it is a plain `a`.

## Accessibility and theme

- The page renders its own `main` landmark and one `h1`, the title of the form or of the expired state; a consumer that wraps it in another `main` ends up with two.
- The block never announces the countdown, only the one minute warning, so the app does not need to throttle the ticks of `expiresIn` for assistive technology.
- Pass a `logo` that carries its own text or `aria-label`; the block adds none.
- The password toggles take their names from `labels.showPassword` and `labels.hidePassword`; translate both with the rest of the labels.
- The block carries no color, radius or shadow of its own: the theme belongs to the app.
