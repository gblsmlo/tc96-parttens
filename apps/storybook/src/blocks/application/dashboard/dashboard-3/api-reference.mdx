# Dashboard3

A team coverage dashboard in four layers: a header with breadcrumb, title, description, period select and Exportar; an optional row of KPI cards; an area chart of staff supply against a dashed forecast line beside an action queue with a button per item; and a crew table with a coverage bar per person, a search and pagination. Reach for it on a scheduling or workforce home page that shows who is covered and what needs a decision. Install it with `npx @tc96/cli add dashboard-3`.

It is a section, not a page: it renders no `main` landmark. The block never fetches and keeps no state. The queue buttons render only when `onAction(id)` is passed, and the app removes or updates the item it resolved. The period select, Exportar, the search and the pagination render only when their callbacks are passed, and the app searches and pages the crew. Coverage is a raw ratio (`0.92`) the block formats with `locale`; `shift` and the series values are the app's. Loading, error and empty are the block's: `pending` renders its skeleton, `error` an error surface with a retry button, and an empty `kpis`, `crew`, `queue` and `forecast` the empty state. The precedence is `pending`, then `error`, then empty.

The other pages of `Blocks/Application/Dashboard/Dashboard3`: [Playground](?path=/story/blocks-application-dashboard-dashboard3-playground--playground) to try the controls, [Behavior](?path=/story/blocks-application-dashboard-dashboard3-behavior--crew-table-shows-member-role-and-shift) for the tests, [States](?path=/story/blocks-application-dashboard-dashboard3-states--default) for the four states and [Usages](?path=/story/blocks-application-dashboard-dashboard3-usages--loaded) for the data read over the network.

## Import

```tsx
import { Dashboard3 } from '@tc96/ui/blocks/application/dashboard/dashboard-3'
```

The same path exports the types listed under Exports.

## Anatomy

Four KPIs, four crew members, three queue items and seven forecast points.

## Dashboard3

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `crew` | `Dashboard3Member[]` | required | The table rows. An empty array renders a message row. |
| `queue` | `Dashboard3QueueItem[]` | required | The action items, in order. An empty array renders a message. |
| `forecast` | `Dashboard3ForecastPoint[]` | required | The points of the line chart. |
| `onAction` | `(id: string) => void` | - | Called with the item `id`; without it no button is rendered. |
| `breadcrumbs` | `{ label: string; href?: string }[]` | - | The trail above the title; the last item is the current page. |
| `renderLink` | `RenderLink` | - | Builds the element of each breadcrumb link, for the app's router; without it the trail is plain text. |
| `period` | `string` | - | The `value` of the active period. |
| `periodOptions` | `{ label: string; value: string }[]` | - | The options of the period select. |
| `onPeriodChange` | `(period: string) => void` | - | Called with the picked period; the select renders only with `period`, `periodOptions` and this callback. |
| `onExport` | `() => void` | - | Renders the Exportar button in the header; hidden on error and on the empty state. |
| `search` | `string` | `''` | The text of the table search. |
| `onSearchChange` | `(search: string) => void` | - | Renders the table search; the app filters the rows. |
| `pagination` | `{ page: number; pageCount: number }` | - | The current page, from 1, and the page count. |
| `onPageChange` | `(page: number) => void` | - | Renders the pagination under the table with `pagination`; the app passes the rows of the page. |
| `kpis` | `Dashboard3Kpi[]` | `[]` | The KPI cards; without them the row is not rendered. |
| `currency` | `string` | `'BRL'` | Currency of the `currency` KPIs. |
| `locale` | `string` | `'pt-BR'` | Locale of every formatted number. |
| `pending` | `boolean` | `false` | Renders the skeleton; wins over `error` and the empty state. |
| `error` | `boolean` | `false` | Renders the error surface; wins over the empty state. |
| `onRetry` | `() => void` | - | Called by the Tentar novamente button; without it the button is not rendered. |
| `labels` | `Partial<Dashboard3Labels>` | pt-BR texts | Overrides the texts of the block; see Labels below. |
| `className` | `string` | - | Merged into the root classes. |

## Data types

| Type | Fields |
| --- | --- |
| `Dashboard3Member` | `id`, `name` (its initials fill the avatar), `role`, `shift`, `coverage` (ratio from 0 to 1), `status` (`{ label, tone? }`) and `avatarSrc`. |
| `Dashboard3QueueItem` | `id`, `title`, `description`, `priority` (`{ label, tone? }`) and `actionLabel`, which replaces `labels.action` on that item. |
| `Dashboard3ForecastPoint` | `label`, `supply` (the area) and `forecast` (the dashed line), both raw numbers. |
| `Dashboard3Kpi` | The same fields as the KPI of `Dashboard1`: `id`, `label`, `value`, `format`, `delta`, `trend` and `sparkline`. |

## Accessibility and theme

- The header is a `header` with the `h2` title; the breadcrumb is a `navigation` named by `labels.breadcrumb` and the period select a `combobox` named by `labels.period`.
- The search is a `searchbox` named by `labels.search`; the pagination is a `navigation` named by `labels.pagination` whose buttons are disabled at the ends.
- The chart is an `img` named by `labels.forecastLabel` and described by a visually hidden text from `labels.forecastSummary`.
- Each coverage bar is a `progressbar` named by `labels.coverageOf` and shows its value as text; each queue button is named by `labels.actionFor`, which keeps the visible text in the name.
- The skeleton is `aria-busy="true"` and named by `labels.loading`; the error surface has the `alert` role.
- Chart colors come from `--chart-1` and `--chart-2`, and the forecast line is dashed so color is not the only cue; status colors come from the theme badge tones. The block carries no raw color, radius or shadow.
