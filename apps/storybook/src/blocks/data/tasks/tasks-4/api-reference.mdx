# Tasks4

`Tasks3` with the view switcher in place of the heading. The list and the Kanban are the same as in `Tasks2`: a column header (Tarefa, Prazo, Projeto, Responsáveis, Atualizada and the author), the tasks grouped by priority, each row with its priority and status icons, title, first tag, due date, project, assignees, last update and author. Install it with `npx @tc96/cli add tasks-4`.

The toolbar `left` slot holds the view switcher (`labels.viewList`): one fixed view named by `labels.title`, then the saved views, with create, update, rename, duplicate and delete when their callbacks are passed. The page has no `h2`; the section keeps its name from `labels.title`. The `right` slot holds, in this order: the filter menu, the layout menu, the sort menu, the group menu and the primary `Action` (`labels.create`). Every control is 32px tall. The filter trigger is an icon button that grows into an icon and a count `Badge` while a filter is active, and its name turns into `labels.activeFilters(count)`. The filter menu holds `labels.filterProperties` with one submenu per property (Status, Prioridade, Responsável), each option with its icon, then `labels.clearFilters`, disabled while no filter is active. The layout menu shows the icon of the current layout and lists Lista and Quadro as radio items; picking one switches the rendered layout. The sort and group menus list their options as radio items with an icon; in the Kanban the group menu offers only Prioridade and Status. The layout, sort and group menus close on a pick.

The block is controlled and renders what it gets. Mode, sort, grouping, collapsed groups, selection and the Status, Prioridade and Responsável filters are a value and a callback; without the value the block keeps it locally. The block does **not** filter or sort `tasks`. Each control renders only with its callback: each filter submenu with its own callback (Responsável also needs `people`), the filter menu with at least one of them, the sort menu with `onSortChange` and the `Action` with `onCreate`. The layout and group menus always render. Picking the fixed view calls `onSavedViewSelect(null)`; the block never applies a saved view.

Every text is a key of `labels`, with pt-BR defaults. Texts that carry a number or a name (`activeFilters`, `selectedCount`, `openTask`, `sortColumn`) are functions, so the consumer decides the word order.

## Import

```tsx
import { Tasks4 } from '@tc96/ui/blocks/data/tasks/tasks-4'
```

## Tasks4

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `tasks` | `Tasks4Task[]` | required | The tasks, already filtered and sorted. |
| `people`, `projects`, `tags` | `Tasks4Person[]`, `Tasks4Option[]`, `Tasks4Tag[]` | `[]` | The catalogs of Responsáveis and author, Projeto, and the tag pills (`tone` colors the dot). |
| `mode`, `onModeChange` | `'list' \| 'kanban'` | `'list'` | The controllable layout, changed from the layout menu. |
| `groupBy`, `onGroupByChange` | `'priority' \| 'status' \| 'project' \| null` | `'priority'` | The controllable grouping; the Kanban reads Prioridade unless it is Status. |
| `collapsedGroupIds`, `onCollapsedGroupIdsChange` | `string[]` | - | Collapsed groups as `<grouping>:<option id>`. Without `collapsedGroupIds` the list keeps them: a group with no tasks starts collapsed, reopens when it gets tasks unless someone toggled it, and the effective list is reported. |
| `sort`, `sortDirection`, `onSortChange` | `Tasks4Sort`, `'asc' \| 'desc'` | `'due'`, the sort's default | The sort menu and the sortable header, rendered with `onSortChange`. |
| `statusFilter`, `priorityFilter`, `assigneeFilter` and their callbacks | `Tasks4Status \| null`, `Tasks4PriorityFilter \| null`, `string \| null` | `null` | The filter submenus; `'none'` in `priorityFilter` stands for Sem prioridade. |
| `filtered` | `boolean` | `false` | Picks `labels.noResult` instead of `labels.empty`. |
| `selectedIds`, `onSelectedIdsChange` | `string[]` | `[]` | The selected tasks; the priority icon of a row turns into its checkbox on hover, focus and touch. |
| `onBulkStatusChange`, `onBulkPriorityChange`, `onBulkProjectChange`, `onBulkAssigneesChange`, `onBulkDelete` | `(taskIds, value?) => void` | - | Any of them enables selection and the `ActionBar` of the list, with no confirmation. |
| `onDueChange`, `onProjectChange`, `onAssigneesChange` | `(taskId, value) => void` | - | Make the row fields editable. |
| `onStatusChange`, `onPriorityChange` | `(taskId, value) => void` | - | Take the Kanban drop. |
| `onOpen` | `(taskId) => void` | - | Makes a row and a card open the task. |
| `onCreate` | `() => void` | - | Renders the primary `Action`, last in the toolbar. |
| `now` | `string` | mount time | The instant Atualizada is compared with. |
| `locale`, `timeZone` | `string` | `'pt-BR'`, `'America/Sao_Paulo'` | Format the dates. |
| `savedViews`, `savedViewId`, `savedViewModified` | `Tasks4SavedView[]`, `string \| null`, `boolean` | - | The saved views after the fixed view; `savedViewId` marks the active one, `savedViewModified` shows `labels.savedViews.modified` and Atualizar visão. |
| `onSavedViewSelect` | `(savedViewId: string \| null) => void` | - | A saved view, or `null` for the fixed view. |
| `onSavedViewCreate`, `onSavedViewUpdate`, `onSavedViewRename`, `onSavedViewDuplicate`, `onSavedViewDelete` | callbacks | - | Each menu action renders with its callback; the dialogs are the consumer's. |
| `savedViewsLoading`, `savedViewsPending` | `boolean` | - | Skeleton for the saved views, and disabled actions while one is saved. |
| `pending`, `error`, `onRetry` | `boolean`, `boolean`, `() => void` | - | The loading contract of the data blocks; the toolbar keeps only the view switcher meanwhile. |
| `labels` | `Tasks4LabelsOverride` | pt-BR texts | Overrides the texts. |
