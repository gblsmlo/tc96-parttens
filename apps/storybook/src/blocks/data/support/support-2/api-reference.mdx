# Support2

A support ticket queue on the collection Data Table (a semantic `<table>`), the same screen as `Support1`: ticket title with code and opening time, requester, queue, priority, SLA and status, with the pattern's `ActionBar` floating over the table while tickets are selected, to assign an owner or move them, and a footer with the rows per page selector. Reach for it on a help desk or operations screen where people triage a queue of items with deadlines. Install it with `npx @tc96/cli add support-2`.

It is a section, not a page: it renders no `main` landmark. The toolbar is one `CollectionToolbar`. Its `left` slot holds either the view switcher, when `views` has items, or `labels.title` as the only `h2` with the summary line as its description, never both; with the switcher the page has no `h2` and the section and the table keep their name from `labels.title`. Its `right` slot holds the search, the `ViewSettings` (Exibição) holding sort, row height and columns, the queue and status filters, Limpar filtros and Salvar visão, and the Exportar CSV and Novo chamado buttons. Every piece of state a consumer saves is controllable and reported: `search`, `queue`, `status`, `sort`, `columnVisibility`, `density`, `selectedIds` and `pageSize`; without the value the table keeps it locally and still calls the callback. The block filters, sorts and pages the rows it receives, but never changes a ticket: Atribuir responsável and Atualizar status are `ActionBar` items whose submenus list the owners and the statuses, and a choice only calls `onAssignOwner` or `onStatusUpdate` with the selected ids. Loading and error are the block's: the toolbar keeps its `left` slot (the view switcher, or the heading without the summary) and hides its controls, `pending` renders the skeleton in place of the table and `error` an error surface with a retry button; the precedence is `pending`, then `error`.

The other pages of `Blocks/Data/Support/Support2`: [Playground](?path=/story/blocks-data-support-support2-playground--playground) to try the controls, [Behavior](?path=/story/blocks-data-support-support2-behavior--each-row-shows-the-ticket-details) for the tests, [States](?path=/story/blocks-data-support-support2-states--default) for the loaded, loading, error and empty states and [Usages](?path=/story/blocks-data-support-support2-usages--loaded) for the data read over the network.

## Import

```tsx
import { Support2 } from '@tc96/ui/blocks/data/support/support-2'
```

The same path exports the types listed under Exports.

## Anatomy

The toolbar with the heading and the summary line (the view switcher takes their place when `views` is passed) and the controls, the table, the `ActionBar` floating over it (only while rows are selected) and the pagination footer with Linhas por página.

```tsx
<Support2
  onAssignOwner={assign}
  onPageSizeChange={setPageSize}
  onSelectedIdsChange={setSelectedIds}
  onStatusUpdate={move}
  owners={owners}
  pageSize={pageSize}
  pageSizeOptions={[6, 12, 24]}
  selectedIds={selectedIds}
  tickets={tickets}
/>
```

## Support2Ticket

| Field | Type | Description |
| --- | --- | --- |
| `id` | `string` | Identifies the row and is what the callbacks receive. |
| `code`, `title` | `string` | The ticket cell; both are searched. |
| `opened` | `string` | The opening time as ready text (`"Aberto há 2 h"`); the block does not compute relative times. |
| `ownerId` | `string \| null` | `null` counts the ticket as unassigned in the summary line. |
| `requester` | `{ name; company; imageUrl? }` | Avatar (initials without image), name and company; name and company are searched. |
| `queue` | `'platform' \| 'billing' \| 'authentication' \| 'integrations'` | The Fila property: a read-only `SelectProperty` with the queue icon and tone. |
| `priority` | `'urgent' \| 'high' \| 'medium' \| 'low'` | The Prioridade property, with the icon, tone and labels every data block shares; sorts by that order. |
| `sla` | `{ label; caption; tone; dueInMinutes }` | The SLA text colored by `tone` (`breached`, `warning`, `healthy`, `closed`) and its caption; `dueInMinutes` sorts the column, `null` goes last. `breached` and `warning` count as near SLA in the summary line. |
| `status` | `'open' \| 'pending' \| 'resolved'` | The Status property, with its icon and tone. |

## Accessibility and theme

- The block renders a semantic `table` with column headers and no grid keyboard model: Tab moves through the checkboxes, the row menus and the toolbar, and sorting lives in Exibição because the header is plain text. Every checkbox is named by the ticket code, the `ActionBar` is a `toolbar` named by `labels.selectionActions`, and the skeleton is `aria-busy="true"` and named by `labels.loading`.
- Queue, priority and status are read-only `SelectProperty` displays (`role="img"`, named `Fila: Plataforma`), whose tone sits only on the icon; the SLA text carries its tone as color and falls back to the foreground on a selected row, because the selected row background drops the warning, success and destructive foregrounds below 4.5:1.
- The block carries no color, radius or shadow of its own beyond token classes: the theme belongs to the app.
