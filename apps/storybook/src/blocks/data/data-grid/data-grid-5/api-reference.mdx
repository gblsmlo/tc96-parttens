# DataGrid5

A task queue on the collection Data Grid where a task carries its sub-tasks: a toolbar with the title, the count and the sub-tasks state, the search, a Configurações menu and Nova tarefa, then Todas, Ativas and Backlog tabs with their counts and a tree grid with the task, its status, the assignee, the priority and the project. Reach for it on a delivery or backlog screen where work splits into smaller steps that ride with their parent. Install it with `npx @tc96/cli add data-grid-5`.

It is a section, not a page: it renders no `main` landmark. The tabs, the expanded rows, the sub-tasks switch and the sort are the consumer's, so they are controlled (`view`, `expanded`, `showSubtasks`, `sort`) and reported (`onViewChange`, `onExpandedChange`, `onShowSubtasksChange`, `onSortChange`). The block never filters `tasks` by tab: the consumer passes the tasks of the current view and the counts of every view. The Data Grid keeps the search, the priority and project filters, the page and the page size locally. The heading is the toolbar's: the `left` slot of one `CollectionToolbar` above the tabs carries `labels.title` as the only `h2` and `labels.summary` as its description. Loading and error are the block's: the toolbar keeps the heading and hides its controls, `pending` renders its skeleton in place of the tabs and the grid, and `error` an error surface with a retry button; the precedence is `pending`, then `error`.

The other pages of `Blocks/Data/DataGrid/DataGrid5`: [Playground](?path=/story/blocks-data-datagrid-datagrid5-playground--playground) to try the controls, [Behavior](?path=/story/blocks-data-datagrid-datagrid5-behavior--header-shows-title-summary-and-create) for the tests, [States](?path=/story/blocks-data-datagrid-datagrid5-states--default) for the loaded, loading, error and empty states and [Usages](?path=/story/blocks-data-datagrid-datagrid5-usages--loaded) for the data read over the network.

## Import

```tsx
import { DataGrid5 } from '@tc96/ui/blocks/data/data-grid/data-grid-5'
```

The same path exports the types listed under Exports.

## Anatomy

The toolbar with the heading, the search, Configurações and Nova tarefa, the tabs, the tree grid with one parent expanded, and the footer with the rows per page selector.

## DataGrid5

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `tasks` | `DataGrid5Task[]` | required | The top-level tasks of the current view, each with its `subtasks`. Keep the array stable between renders, or the page resets. |
| `view` | `'all' \| 'active' \| 'backlog'` | `'all'` | The selected tab. |
| `onViewChange` | `(view: DataGrid5View) => void` | - | The tabs render only with this callback. The block does not filter `tasks`. |
| `viewCounts` | `Record<DataGrid5View, number>` | - | The count badge of each tab; without it the tabs show only their names. |
| `expanded` | `true \| Record<string, boolean>` | - | Controls which parents show their sub-tasks, keyed by task id; without it the grid keeps it locally. |
| `onExpandedChange` | `(expanded: DataGrid5Expanded) => void` | - | Called with the resolved state on every toggle. |
| `showSubtasks` | `boolean` | `true` | Off, the grid shows only the top-level tasks as a plain grid and the summary says the sub-tasks are hidden. |
| `onShowSubtasksChange` | `(showSubtasks: boolean) => void` | - | The Mostrar subtarefas switch of Configurações renders only with this callback. |
| `sort` | `DataGrid5Sort \| null` | - | Controls the sort; status and priority sort by their workflow order, not alphabetically. |
| `onSortChange` | `(sort: DataGrid5Sort \| null) => void` | - | Called once per sort change, from Ordenar por or from a column menu. |
| `pageSize` | `number` | `5` | Initial rows per page. Pages count top-level tasks; sub-tasks ride with their parent. |
| `pageSizeOptions` | `readonly number[]` | `[5, 10, 20]` | The options of the rows per page selector. |
| `rowActions` | `DataGrid5RowAction[]` | - | The items of the row menu (`{ id, label, destructive? }`). |
| `onRowAction` | `(actionId: string, taskId: string) => void` | - | The menu column renders only with this callback and `rowActions`. |
| `onCreate` | `() => void` | - | The Nova tarefa button renders only with this callback. |
| `pending` | `boolean` | `false` | Renders the skeleton below the heading; wins over `error`. |
| `error` | `boolean` | `false` | Renders the error surface. |
| `onRetry` | `() => void` | - | Called by the Tentar novamente button; without it the button is not rendered. |
| `labels` | `DataGrid5LabelsOverride` | pt-BR texts | Overrides the texts; `columns`, `statuses`, `priorities` and `views` merge key by key. Keep the object stable, because the columns are rebuilt when it changes. |
| `className` | `string` | - | Merged into the root classes. |

## DataGrid5Task

| Field | Type | Description |
| --- | --- | --- |
| `id` | `string` | Identifies the row and the key of `expanded`; unique across parents and sub-tasks. |
| `title` | `string` | The task cell, struck through when the status is `done`. |
| `status` | `'backlog' \| 'todo' \| 'inProgress' \| 'review' \| 'done'` | The status badge with its dot, and the check icon of the task cell. |
| `assignee` | `{ id; label; imageUrl? }` | The avatar and the name. |
| `priority` | `'urgent' \| 'high' \| 'medium' \| 'low'` | The priority badge and the Prioridade filter. |
| `project` | `string` | The project badge and the Projeto filter, whose options come from every task and sub-task. |
| `subtasks` | `DataGrid5Task[]` | Optional; a task with sub-tasks gets the expand button. |

## Accessibility and theme

- With sub-tasks the grid is a WAI-ARIA `treegrid`: rows carry `aria-level`, a parent carries `aria-expanded`, and the expand button, named by `labels.expand` or `labels.collapse`, is the keyboard path (Tab, then Enter or Space), because the arrow keys move the cell focus. With `showSubtasks` off it is a plain `grid`.
- The tabs are a `tablist` named by `labels.viewsLabel`; the grid sits in the selected `tabpanel`, and the toolbar sits above the tabs.
- The status dot and the check icon are decorative: the status badge carries the text, so a done task never depends on the strike-through alone.
- The skeleton is `aria-busy="true"` and named by `labels.loading`; the error surface has the `alert` role.
- The block carries no color, radius or shadow of its own beyond token classes: the theme belongs to the app.
