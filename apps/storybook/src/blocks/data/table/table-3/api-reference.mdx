# Table3

A renewals review on the collection Data Table (a semantic `<table>`), the same screen as `DataGrid3`: account with owner and segment, renewal due date, ARR with upside, health, stage and risk, filtered by condition chips (field, operator, value) and with the pattern's `ActionBar` floating over the table while renewals are selected, to reassign the owner or move the stage. Reach for it on a customer success or revenue screen where people narrow a portfolio with several criteria at once. Install it with `npx @tc96/cli add table-3`.

It is a section, not a page: it renders no `main` landmark. The conditions belong to the consumer: `conditions` feeds the table's global filter through `createDataGridConditionFilterFn` (typed with `DataTableFeatures`), and the `DataGridConditionFilters` chips, the Filtros field menu and Limpar filtros report through `onConditionsChange`; without that callback the chips are not rendered but the conditions still filter. The chips sit in their own row below the toolbar. The toolbar is one `CollectionToolbar`. Its `left` slot holds either the view switcher, when `views` has items, or `labels.title` as the only `h2` with the summary line as its description, never both; with the switcher the page has no `h2` and the section and the table keep their name from `labels.title`. Its `right` slot holds the `ViewSettingsMenu` (Configurações) holding sort, row height, columns, Limpar filtros and Salvar view, and the Nova transação button. The sort, the column visibility, the density and the selection are controllable and reported. The block never changes a renewal: Atribuir responsável and Mover etapa are `ActionBar` items whose submenus list the owners and the stages, and a choice only calls `onAssignOwner` or `onStageUpdate` with the selected ids. Loading and error are the block's: the toolbar keeps its `left` slot (the view switcher, or the heading without the summary) and hides its controls and the chips, `pending` renders the skeleton in place of the table and `error` an error surface with a retry button; the precedence is `pending`, then `error`.

The other pages of `Blocks/Data/Table/Table3`: [Playground](?path=/story/blocks-data-table-table3-playground--playground) to try the controls, [Behavior](?path=/story/blocks-data-table-table3-behavior--each-row-shows-the-renewal-details) for the tests, [States](?path=/story/blocks-data-table-table3-states--default) for the loaded, loading, error and empty states and [Usages](?path=/story/blocks-data-table-table3-usages--loaded) for the data read over the network.

## Import

```tsx
import { Table3 } from '@tc96/ui/blocks/data/table/table-3'
```

The same path exports the types listed under Exports.

## Anatomy

The toolbar with the heading and the summary line (the view switcher takes their place when `views` is passed), Configurações and Nova transação, the condition chips with Filtros and Limpar filtros, the table, the `ActionBar` floating over it (only while rows are selected) and the pagination footer.

## Table3

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `renewals` | `Table3Renewal[]` | required | The rows. Keep the array stable between renders. |
| `conditions` | `readonly Table3Condition[]` | `[]` | The filter conditions; an incomplete one (no value) does not filter. Conditions join with AND. |
| `onConditionsChange` | `(conditions: Table3Condition[]) => void` | - | Called by every chip change, the Filtros menu, the chip menu, Limpar filtros and the Limpar filtros item of Configurações; the chips render only with it. The page goes back to the first. |
| `sort` | `Table3Sort \| null` | - | Controls the sort; risk and stage sort by their order, not alphabetically. |
| `onSortChange` | `(sort: Table3Sort \| null) => void` | - | Called once per sort change, from Configurações > Ordenar por; the table has no column menu. |
| `columnVisibility` | `Table3ColumnVisibility` | all visible | Controls the visible columns; a column is hidden only when its value is `false`. |
| `onColumnVisibilityChange` | `(visibility: Table3ColumnVisibility) => void` | - | Called once per change. |
| `density` | `Table3Density` | `"tall"` | Row height. |
| `onDensityChange` | `(density: Table3Density) => void` | - | With it, `density` is controlled and Configurações > Altura das linhas reports here. |
| `selectedIds` | `string[]` | - | Controls the selected renewal ids. |
| `onSelectedIdsChange` | `(renewalIds: string[]) => void` | - | Called on every selection change, Limpar seleção included. |
| `owners` | `Table3Person[]` | the owners found in `renewals` | The items of the Atribuir responsável submenu of the `ActionBar` and the options of the Responsável condition. |
| `onAssignOwner` | `(renewalIds: string[], ownerId: string) => void` | - | Called by an owner of Atribuir responsável; the item renders only with it and at least one owner. |
| `onStageUpdate` | `(renewalIds: string[], stage: Table3Stage) => void` | - | Called by a stage of Mover etapa; the item renders only with it. |
| `views`, `activeViewId`, `onViewChange`, `onViewCreate` | `GridViewProps` | - | The shared view switcher, which replaces the heading and the summary line in the toolbar; without items in `views` the heading shows. The block does not apply a view. |
| `onSaveView` | `() => void` | - | Renders Salvar view at the end of Configurações. |
| `onCreate` | `() => void` | - | Renders the Nova transação button. |
| `rowActions`, `onRowAction` | `Table3RowAction[]`, `(actionId, renewalId) => void` | - | The row menu column renders only with both. |
| `pageSize` | `number` | `10` | Rows per page of the footer. |
| `locale`, `currency` | `string` | `"pt-BR"`, `"BRL"` | Format of the ARR, upside, percentages, dates and the summary amount. |
| `pending`, `error`, `onRetry` | `boolean`, `boolean`, `() => void` | - | The shared load state; `pending` wins over `error`, and the retry button renders only with `onRetry`. |
| `labels` | `Partial<Table3Labels>` | pt-BR texts | Overrides the texts; the records merge key by key. Keep the object stable, because the columns are rebuilt when it changes. |
| `className` | `string` | - | Merged into the root classes. |

## Table3Renewal

| Field | Type | Description |
| --- | --- | --- |
| `id` | `string` | Identifies the row and is what the callbacks receive. |
| `account` | `{ name; segment; logoUrl? }` | The logo tile (the first initial without `logoUrl`), the name and the segment (`enterprise`, `mid-market`, `scale`). |
| `owner` | `Table3Person` | The small avatar and name under the account; filterable as Responsável. |
| `renewalDate` | `string` | ISO date, shown under the due text and filtered by the date condition. |
| `dueInDays` | `number` | The due text: overdue below 0, soon up to 30 days, later beyond; up to 14 days the text is destructive, up to 30 warning. |
| `arr`, `upside` | `number` | Raw amounts formatted with `locale` and `currency`; a positive upside is green. |
| `health` | `number` | Ratio from 0 to 1: a bar, the percentage and the level (below 0.55 Em risco, below 0.75 Em observação, else Saudável). Its condition takes the percentage (0 to 100). |
| `stage` | `'preparing' \| 'commercial-review' \| 'legal-review' \| 'signed'` | The stage badge with its dot. |
| `risk` | `'critical' \| 'high' \| 'medium' \| 'low'` | The risk badge with its dot. |

The summary counts, over the filtered rows, the renewals due within 30 days, the ones at risk (`critical` risk or health level Em risco) and the ARR of those at risk.

## Accessibility and theme

- Each condition chip is a group named by `conditions.condition(field)`; its operator, value and actions are buttons, and the value editor is named by `conditions.editValue(field)`.
- The block renders a semantic `table` with column headers and no grid keyboard model: Tab moves through the checkboxes, the row menus, the chips and the toolbar, and sorting lives in Configurações because the header is plain text.
- The `ActionBar` is a `toolbar` named by `labels.selectionActions`, and each choice of Atribuir responsável and Mover etapa is a `menuitem` under its group label.
- The health bar is decorative with a hidden `healthScore` text; stage and risk are outline badges whose color sits only on the dot.
- The due text and the upside carry their tone as color and fall back to the foreground on a selected row, because the selected row background drops the warning, success and destructive foregrounds below 4.5:1.
- The block carries no color, radius or shadow of its own beyond token classes: the theme belongs to the app.
