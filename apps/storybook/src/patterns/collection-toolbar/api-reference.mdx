# CollectionToolbar

The bar above a collection of records, for the controls that act on the whole view: the saved view the user is looking at, the display settings, a search field, the main action. `CollectionToolbar` is the frame: it places the controls in a left, a center and a right slot, sets the surface with `mode` and keeps no state of its own.

The other pages of `Patterns/CollectionToolbar`: [Playground](?path=/story/patterns-collectiontoolbar-playground--playground) to try the mode and what fills each slot, [Layouts](?path=/story/patterns-collectiontoolbar-layouts--default) for the arrangements of the slots, [Behavior](?path=/story/patterns-collectiontoolbar-behavior--slots-stay-out-of-the-dom-in-order) for the tests, and [Usages](?path=/story/patterns-collectiontoolbar-usages--task-views) for real toolbars, each filling one of the layouts: a view switcher, a heading, a search field on the side or at the center, a group of shortcuts, the view settings alone.

Used in: the collection frame places the toolbar above every layout, with the view switcher on the screens that have saved views. See the toolbar of [Tasks](?path=/story/patterns-collection-usages--tasks), [Pipeline](?path=/story/patterns-collection-usages--pipeline) and [Contacts](?path=/story/patterns-collection-usages--contacts), and the toolbar over a layout in [Data Grid](?path=/docs/patterns-collection-layouts-data-grid-api-reference--api-reference) and [Data Table](?path=/docs/patterns-collection-layouts-data-table-api-reference--api-reference).

The controls a screen puts in the slots have their own pages: [ViewSwitcher](?path=/docs/patterns-viewswitcher-api-reference--api-reference) for the saved views and [ViewSettings](?path=/docs/patterns-viewsettings-api-reference--api-reference) for the display settings; `CollectionSearchField`, `Action`, `PresetsMenu` and `FilterRadioSubmenu` belong to [Patterns/Collection](?path=/docs/patterns-collection-api-reference--api-reference). They render toolbar buttons and inputs, so they only mount inside a `CollectionToolbar`.


The toolbar renders its groups itself around the slots. The tree it renders:

```text
div[role=toolbar][data-slot=toolbar][data-mode]
├── div[role=group][data-slot=toolbar-group]   left
│   or div[aria-hidden]                        spacer, only with center and no left
├── div[role=group][data-slot=toolbar-group]   center, only with center
└── div[role=group][data-slot=toolbar-group]   right
    or div[aria-hidden]                        spacer, only with center and no right
```

## CollectionToolbar

The frame for the controls of a collection. Renders a `div` with `role="toolbar"`, named by `aria-label`, that lays out its three slots on one row. It takes no `children`: content enters only through the slots. It keeps no state: the consumer composes the controls, and the toolbar never fetches, filters or runs anything.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `mode` | `"default"` or `"plain"` | `"plain"` | Controls the surface: `"default"` keeps the framed bar, `"plain"` sits straight on the page. |
| `left` | `ReactNode` | - | Sets the content at the start of the bar, such as a heading or the view switcher. |
| `center` | `ReactNode` | - | Sets the controls at the middle of the bar, such as a period toggle. |
| `right` | `ReactNode` | - | Sets the controls at the end of the bar, such as the view settings and the main action. |
| `aria-label` | `string` | `"Controles da coleção"` | Names the toolbar for assistive technology. |
| `className` | `string` | - | Adds classes after the bar classes, so a conflicting class wins. |

Also takes every prop of Base UI `Toolbar.Root` (a `div`), such as `orientation`, `disabled` and `loopFocus`, except `children`.

| Attribute | Values | Description |
| --- | --- | --- |
| `data-slot` | `"toolbar"` | Selects the bar in the theme and in tests |
| `data-mode` | `"default"` or `"plain"` | Follows `mode`, so the theme can tell the surfaces apart |
| `data-orientation` | `"horizontal"` or `"vertical"` | Follows `orientation` |
| `data-disabled` | present when `disabled` | Lets the theme style a disabled toolbar |

The slots are never DOM attributes: `left`, `center` and `right` are read by the toolbar and each one is wrapped in its own group. The `"default"` mode is a bordered, rounded and padded bar on the card background; `"plain"` removes the border, the radius, the background and the padding. The bar is at least 36px tall (40px from `md`) and grows with its content, such as a heading with a description in `left`.

Without `center` the right group takes `ms-auto` and sits at the end. With it, the left and right groups share the remaining width equally (`flex-1 basis-0`) and an `aria-hidden` spacer stands in for a side that has no slot, so the center group sits at the middle of the toolbar whatever the width of the sides.

The toolbar is one Tab stop, and the arrow keys move focus between its items: the trigger of `ViewSwitcherMenu`, `Action`, the triggers of `ViewSettingsMenu` and `PresetsMenu`, the field of `CollectionSearchField` and any `ToolbarButton` in a slot. A plain `button` is not an item and stays a tab stop of its own.

## CollectionToolbarGroup

A group of controls inside a slot, named by `aria-label` when the slot holds more than one group. Renders a `div` with `role="group"`, a row with 4px between its controls.

Also takes every prop of Base UI `Toolbar.Group` (a `div`), such as `disabled`, which disables every item in the group, and `aria-label`.

| Attribute | Values | Description |
| --- | --- | --- |
| `data-slot` | `"toolbar-group"` | Selects a group; the groups the toolbar draws around its slots carry it too |
| `data-orientation` | `"horizontal"` or `"vertical"` | Follows the orientation of the toolbar |
| `data-disabled` | present when disabled | Lets the theme style a disabled group |

| Export | Kind | Description |
| --- | --- | --- |
| `CollectionToolbarProps` | `type` | The props of `CollectionToolbar`. |

| `CollectionToolbarGroupProps` | `type` | The props of `CollectionToolbarGroup`. |

## Accessibility and theme

- Name the toolbar with `aria-label` so it says which collection it controls; the default is in Portuguese, so pass a name in the language of the screen.
- The framed bar reads `--card`, `--card-foreground`, `--border` and `--radius-xl`.
