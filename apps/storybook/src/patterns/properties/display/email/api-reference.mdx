# Email

A property for a short list of email addresses: the work and personal address of a contact, the billing address of an account. The addresses show as a row of chips with an add trigger at the end, or as one trigger that summarizes them; new addresses are typed in a popup with one field per entry, or in a field that takes the place of the trigger. The consumer keeps the list and receives the next one.

The other pages of `Patterns/Properties/Display/Email`: [Playground](?path=/story/patterns-properties-display-email-playground--playground) to try the addresses, the texts, the states and the add trigger, [Stories](?path=/story/patterns-properties-display-email-stories--default) for each state and display, [Behavior](?path=/story/patterns-properties-display-email-behavior--empty-trigger-names-itself) for the tests, [Usages](?path=/story/patterns-properties-display-email-usages--contact-emails) for real content, and [Layouts](?path=/story/patterns-properties-display-email-layouts--without-add-trigger) for the row without the add trigger.

Used in: the contact of [Templates/Contact Detail](?path=/story/templates-contact-detail--default) and the dialog of [Patterns/Records/RecordDialog/Usages, Contacts](?path=/story/patterns-records-recorddialog-usages--contacts).

## EmailProperty

Renders a `fieldset` named by `ariaLabel`, or, with `display="trigger"`, a single `button`. It never sends, verifies or stores an address: it checks the format, rejects a repeated address, and hands the next list to `action` or `onValueChange`. It is read-only when `readOnly` is set or when neither `action` nor `onValueChange` is passed; with both, only `action` is called.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `value` | `readonly string[]` | required | Sets the addresses, in order. |
| `onValueChange` | `(value: readonly string[]) => void` | - | Called with the next list after a save, an inline add or a removal. |
| `action` | `(value: readonly string[], context: EmailPropertyActionContext) => void` | - | Called instead of `onValueChange`, with what changed. |
| `display` | `"chips"` or `"trigger"` | `"chips"` | Controls the display: a row of chips with an add trigger, or one trigger that names the property and summarizes the list. |
| `editing` | `"popover"` or `"inline"` | `"popover"` | Controls how the chips row adds an address: in the entry popup, or in a field that takes the place of the add trigger. |
| `variant` | `"badge"` or `"plain"` | `"plain"` | Controls the surface of the read-only chips and of the `trigger` display. |
| `entryLabels` | `readonly string[]` | `["Principal", "Secundário"]` | Names the fields of the popup, one per address, and so sets how many addresses the popup holds. |
| `placeholder` | `string` | `"Sem e-mail"` | Sets the text of the add trigger and of the read-only row while there is no address. |
| `addLabel` | `string` | `"Adicionar e-mail"` | Names the add trigger, the popup and the inline field. |
| `ariaLabel` | `string` | `"E-mails"` | Names the row, and prefixes the name of the `trigger` display. |
| `inputPlaceholder` | `string` | `"nome@exemplo.com"` | Sets the placeholder of the fields. |
| `errorMessage` | `string \| null` | `null` | Sets a rejection of the consumer, shown with `role="alert"` in the popup and under the inline field. |
| `addDisabled` | `boolean` | `false` | When true, removes the add trigger from the chips row. |
| `disabled` | `boolean` | `false` | When true, disables the add trigger, the remove buttons and the `trigger` display. |
| `readOnly` | `boolean` | `false` | When true, shows the addresses with no add trigger and no remove buttons. |
| `className` | `string` | - | Adds classes to the row, or to the trigger with `display="trigger"`. |

Takes no other prop.

| Attribute | Values | Description |
| --- | --- | --- |
| `data-slot` | `"email-property"` | Selects the row |
| `data-variant` | `"badge"` or `"plain"` | Follows `variant` on the row |
| `data-editing` | `"popover"` or `"inline"` | Follows `editing` on an editable chips row |
| `data-slot` | `"property-surface"` | Selects each chip, and the add trigger of `editing="inline"` |
| `data-slot` | `"popover-trigger"` | Selects the add trigger that opens the popup and the `trigger` display: the slot of the popover trigger replaces `"property-surface"` on them |
| `data-variant` | `"badge"` or `"plain"` | Follows the surface on each chip and trigger |
| `data-empty` | `"true"` while there is no address | Styles the empty add trigger and the empty `trigger` display |
| `data-slot` | `"property-icon"` | Selects the mail icon of the `trigger` display |

### The chips row

Each address is a badge with a mail icon and a 24px remove button named `"Remover e-mail <address>"`; a click removes the address at once. The chips of an editable row are badges whatever `variant` says: `variant` reaches only `data-variant` there. The add trigger comes last: with no address it shows the mail icon and `placeholder`, with addresses it shrinks to a 24px `+`, and both are named by `addLabel` and announce a dialog (`aria-haspopup="dialog"`, `aria-expanded`).

### The entry popup

The popup is a 320px popover named by `addLabel`, with one `type="email"` field per address, or a single empty field when there is none, each named by its entry label; the labels show above the fields when there is more than one. `Adicionar outro` adds a field while there are fewer fields than `entryLabels` and every field holds a valid address. `Salvar`, or Enter in a field, saves: empty fields are dropped, each field is trimmed and checked, and a bad one shows `"Informe um e-mail válido."` or `"Este e-mail já está na lista."` under it, with `role="alert"`, and keeps the popup open. A valid save calls the handler once with the whole list and closes the popup. The fields copy `value` when the popup opens, so a new `value` while it is open does not overwrite what is being typed.

### Inline editing

With `editing="inline"` the add trigger gives way to a 192px field named by `addLabel`, with no popup. Leaving the field or pressing Enter commits: an empty field closes with no change, a bad or repeated address keeps the field open with the text and shows the message under it, and a valid one is added to the end of the list and closes the field. The field does not take focus when it opens, and it adds one address at a time with no limit from `entryLabels`.

### The trigger display

With `display="trigger"` there is no row and no chip: one button with the mail icon and a summary, the first address plus `"+N"` for the others, or `placeholder` while there is none. It is named `"<ariaLabel>: <summary>"`, or `ariaLabel` alone while empty, and opens the same popup to add, change or remove addresses. Its surface is a badge unless `variant` is `"plain"`; the plain trigger draws a `secondary` box on hover, on keyboard focus and while the popup is open (see [`PropertySurface`](?path=/docs/patterns-properties-api-reference--api-reference)).

### Read-only

A read-only `EmailProperty` renders the row with one `IconLabelProperty` per address, on the `variant` surface, or a muted surface with `placeholder` while there is no address. It has no button.

## EmailPropertyActionContext

What `action` receives with the next list.

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `added` | `string \| null` | - | The first address the next list has and the previous one did not. |
| `removed` | `string \| null` | - | The first address the previous list had and the next one does not. |
| `previousValue` | `readonly string[]` | - | The list before the change. |

A save that adds and removes several addresses at once reports only the first of each.

## Accessibility and theme

- The texts are Brazilian Portuguese: pass `placeholder`, `addLabel`, `ariaLabel` and `entryLabels` to change them. The format and repeat messages, `Adicionar outro`, `Salvar` and the remove names cannot be changed.
- With `editing="inline"`, pressing the add trigger removes it and does not move focus to the field that replaces it, so focus falls to the page and keyboard users lose their place.
- The error messages read `destructive-foreground`; the chips and trigger read the badge tokens of the property surface.
