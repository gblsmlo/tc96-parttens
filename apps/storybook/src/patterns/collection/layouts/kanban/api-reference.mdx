# Kanban

A board of columns of cards for a collection grouped by one dimension: deals by stage, tasks by status, campaigns by objective. The consumer passes the columns with their cards, returns each card from `renderCard`, usually built from the `KanbanCard` parts, and decides whether a card moved between or inside columns is accepted.

The other pages of `Patterns/Collection/Layouts/Kanban`: [Playground](?path=/story/patterns-collection-layouts-kanban-playground--playground) to try the column states, the card display and the optional parts, [Stories](?path=/story/patterns-collection-layouts-kanban-stories--default) for each state, [Behavior](?path=/story/patterns-collection-layouts-kanban-behavior--loading-keeps-card-height) for the tests, [Usages](?path=/story/patterns-collection-layouts-kanban-usages--tasks) for a board of tasks and [Layouts](?path=/story/patterns-collection-layouts-kanban-layouts--title-only-cards) for the card parts and the column header actions.

Used in: [Patterns/Collection/Usages, Pipeline](?path=/story/patterns-collection-usages--pipeline), a board of deals by stage, and [Tasks](?path=/story/patterns-collection-usages--tasks) and [Campaigns](?path=/story/patterns-collection-usages--campaigns), where `CollectionLayoutOutlet` mounts the board from its `kanban` prop and `renderKanbanRecord`.

## Anatomy

<Canvas of={ApiReferenceStories.Anatomy} />

```tsx
<KanbanView
  columns={columns}
  emptyColumnLabel="emptyColumnLabel"
  getColumnActions={() => ({ onAddCard, onOpenSettings })}
  getKey={(card) => card.id}
  renderCard={(card) => <KanbanCard>{/* the card parts */}</KanbanCard>}
/>
```

`KanbanView` renders one column per entry of `columns`, with a header (the color marker, the title, the count and the actions) and the cards `renderCard` returns. The card is the consumer's, built from these parts:

<Canvas of={ApiReferenceStories.CardAnatomy} />

```tsx
<KanbanCard variant="interactive">
  <KanbanCardOpenTrigger aria-label="Abrir negócio" onClick={open} />
  <KanbanCardHeader>
    <KanbanCardTitle />
    <KanbanCardDescription />
    <KanbanCardAction />
  </KanbanCardHeader>
  <KanbanCardBody>
    <KanbanCardField>
      <KanbanCardFieldLabel />
      <KanbanCardFieldValue />
    </KanbanCardField>
  </KanbanCardBody>
  <KanbanCardFooter>
    <KanbanCardControl />
  </KanbanCardFooter>
</KanbanCard>
```

Every part but `KanbanCard` is optional. While `loading`, a `KanbanCardSkeleton` takes the place of each card:

## KanbanView

The board. Renders a `div`, with no role, that takes the full height of its parent, so its parent needs a bounded height. It never fetches, sorts, filters or stores the cards: it shows the `columns` it receives, and a move reaches the consumer through `onMoveCard`.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `columns` | `KanbanColumnData<TCard>[]` | required | Sets the columns, in order, with their cards. |
| `getKey` | `(card: TCard) => string \| number` | required | Returns the key of a card, unique on the board. |
| `renderCard` | `(card: TCard) => React.ReactNode` | required | Returns the whole card. |
| `onMoveCard` | `(move: KanbanCardMove<TCard>) => boolean \| Promise<boolean>` | - | Called when a card is dropped in another column or position; returns whether the move is accepted. Turns on card drag. |
| `getCardLabel` | `(card: TCard) => string` | - | Returns the name of a card in its drag handle, `Mover card <label>`; without it the handle uses the key. |
| `getColumnActions` | `(column: KanbanColumnData<TCard>) => KanbanColumnActions \| undefined` | - | Returns the add and settings actions of a column header. |
| `renderColumnTitle` | `(column: KanbanColumnData<TCard>) => React.ReactNode` | - | Replaces the text of a column heading. |
| `renderHeaderActions` | `(column: KanbanColumnData<TCard>) => React.ReactNode` | - | Adds content after the header buttons of a column. |
| `emptyColumnLabel` | `string` | `"Nenhum item nesta coluna."` | Sets the text of a column with no cards. |
| `loading` | `boolean` | `false` | When true, replaces the cards with skeletons, hides the column actions, turns off drag and sets `aria-busy`. |
| `loadingCardAnatomy` | `KanbanCardSkeletonAnatomy` | - | Sets the parts of each skeleton, so it matches the card. |
| `loadingCardCount` | `number` | `1` | Sets the number of skeletons in each column while loading. |
| `loadingCardLabel` | `string` | - | Names each skeleton; without it the skeleton is named `"Carregando card"`. |
| `mobileColumnHint` | `string` | - | Adds a line of help under the column selector, below `md`. |

| Attribute | Values | Description |
| --- | --- | --- |
| `data-slot` | `"kanban-view"` | Selects the board |
| `aria-busy` | `"true"` while `loading` | Marks the board as loading |

The board has two layouts in the DOM and CSS shows one. From the `md` breakpoint, every column that is not `hidden` sits side by side in a horizontal scroll area, 304px wide each (352px from `xl`) with 8px between them. Below `md`, a row of toggle buttons named `<title> · <count>` (`aria-pressed` on the active one), under the label `Coluna`, picks the one column shown. The cards of the active column therefore render twice: keep `renderCard` pure, and do not emit DOM ids in it.

### Moving cards

With `onMoveCard` and not `loading`, each card on the desktop board gets a drag handle: a button named `Mover card <label>` at its top-left corner, visible only when it has keyboard focus. Space picks the card up, the arrow keys move it between and inside columns, Space or Tab drops it and Escape cancels. A pointer drags the whole card after 5px of movement (on touch, after a 250ms press within 5px), except from a control inside it, such as a button, a field or a menu; a drag can start on `KanbanCardOpenTrigger`. Below `md` and on a collapsed column, no card can be dropped.

When the card is dropped, the board shows it at the target at once and calls `onMoveCard`. `true` keeps it there until `columns` shows the card at the target; `false`, a thrown error or a rejected promise puts it back. A promise ends the drop animation at once, without waiting for it to settle. Focus returns to the handle of the moved card. While cards can be dragged, a pointer drag of more than 8px on the board outside a card and its controls scrolls the board sideways, and a click within 500ms after such a drag is ignored.

## KanbanColumnData

A column the consumer passes in `columns`.

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `id` | `string` | required | Identifies the column in `onMoveCard` and the column actions. |
| `title` | `string` | required | Sets the heading, which names the column. |
| `count` | `number` | required | Sets the number in the header badge; the board does not count `cards`. |
| `cards` | `TCard[]` | required | Sets the cards, in order. |
| `color` | `string` | - | Sets a CSS color for the marker dot, a 4% tint of the column surface and an 8% tint of its border. |
| `collapsed` | `boolean` | - | When true, narrows the column to 48px with a vertical title, and hides its cards and its add button. |
| `hidden` | `boolean` | - | When true, leaves the column out of the board and the selector. |

Each column renders a `section` named by its `h2` heading, so it is a `region` landmark.

| Attribute | Values | Description |
| --- | --- | --- |
| `data-slot` | `"kanban-column"` | Selects a column |
| `data-collapsed` | `"true"` when `collapsed` | Styles a collapsed column |

## KanbanColumnActions

What `getColumnActions` returns for a column. Each callback adds an icon button to the header, named by its label, and receives the column `id`.

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `onAddCard` | `(columnId: string) => void` | - | Called when the plus button is clicked; the button is not rendered on a collapsed column. |
| `onOpenSettings` | `(columnId: string) => void` | - | Called when the settings button is clicked. |
| `addLabel` | `string` | `"Adicionar item à seção <title>"` | Names the plus button. |
| `settingsLabel` | `string` | `"Configurar seção <title>"` | Names the settings button. |

## KanbanCardMove

What `onMoveCard` receives.

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `card` | `TCard` | required | The moved card. |
| `cardId` | `string` | required | The card key, as a string. |
| `sourceColumnId` | `string` | required | The column the card started in. |
| `targetColumnId` | `string` | required | The column it was dropped in; the same as `sourceColumnId` for a reorder. |
| `sourceIndex` | `number` | - | The position it started at. |
| `targetIndex` | `number` | - | The position it was dropped at. |

## KanbanCard

The card. Renders a `Card` as an `article`, with no content of its own: the consumer fills its parts. It never opens, selects or moves itself; it shows the state its props set.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `display` | `"full"` or `"compact"` | `"full"` | Controls the parts shown: `compact` hides the description, the body and the footer, and keeps the header on one line. |
| `variant` | `"default"` or `"interactive"` | `"default"` | Controls the cursor and focus ring of a card that opens. |
| `density` | `"sm"` or `"md"` | `"sm"` | Sets `data-density` and the `--card-padding` and `--card-section-gap` variables. |
| `selected` | `boolean` | `false` | When true, draws a ring around the card and sets `data-state="selected"`. |
| `dimmed` | `boolean` | `false` | When true, draws a dashed border with no shadow, as for a card being moved. |
| `render` | `React.ReactElement` or `(props) => React.ReactElement` | - | Replaces the `article` with another element. |

Also takes every prop of an `article`.

| Attribute | Values | Description |
| --- | --- | --- |
| `data-slot` | `"card"` | Selects the card; the theme's card rule sets its radius |
| `data-pattern` | `"kanban-card"` | Tells a kanban card from other cards |
| `data-display` | `"full"` or `"compact"` | Styles the card by display |
| `data-variant` | `"default"` or `"interactive"` | Styles the card by variant |
| `data-density` | `"sm"` or `"md"` | Styles the card by density |
| `data-state` | `"selected"` when `selected` | Styles a selected card |

`density` sets `--card-padding` and `--card-section-gap` (16px and 8px at `"sm"`, 24px and 16px at `"md"`), but no part of the card reads them: the parts have fixed padding, so both densities look the same.

The card draws a 2px `primary` ring when any element inside it has keyboard focus, since the open trigger has no outline of its own, and a lighter fill on hover. Any element inside the card with `data-kanban-card-action` sits above the open trigger: `KanbanCardAction`, `KanbanCardActionButton`, `KanbanCardControl` and an `interactive` `KanbanCardFieldValue` set it.

### KanbanCardOpenTrigger

The button that opens the card. Renders a `button` with `type="button"`, stretched over the whole card, with no text: name it with `aria-label`. It is the keyboard path to the record; without it the card has no button of its own. Clicks on the controls of the card do not reach it. Also takes every prop of a `button`.

| Attribute | Values | Description |
| --- | --- | --- |
| `data-slot` | `"kanban-card-open-trigger"` | Selects the trigger |

### KanbanCardHeader, KanbanCardTitle, KanbanCardDescription, KanbanCardAction

The header holds the title, the description and the action, as a `CardHeader` with 12px of padding (8px at the bottom); in `compact` it is one row at least 40px tall. `KanbanCardTitle` is a `div` in `font-medium` `text-sm`, truncated to one line in `compact`. `KanbanCardDescription` is a muted `div` in `text-xs`, clamped to three lines and hidden in `compact`. `KanbanCardAction` is the cell at the end of the header, for a menu. Each takes every prop of a `div`.

| Attribute | Values | Description |
| --- | --- | --- |
| `data-slot` | `"card-header"`, `"card-title"`, `"card-description"` or `"card-action"` | Selects each part |
| `data-kanban-card-action` | `""` on `KanbanCardAction` | Raises it above the open trigger |

### KanbanCardActionButton

A small ghost button for the header menu. Renders a `button` with `type="button"`, 28px tall.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `size` | `"default"` or `"icon"` | `"default"` | Controls the shape: `icon` is a 28px square. |
| `render` | `React.ReactElement` or `(props) => React.ReactElement` | - | Replaces the `button`, as a menu trigger does. |

Also takes every prop of a `button`. Name an icon-only button with `aria-label`.

| Attribute | Values | Description |
| --- | --- | --- |
| `data-slot` | `"kanban-card-action-button"` | Selects the button |
| `data-kanban-card-action` | `""` | Raises it above the open trigger |

### KanbanCardBody, KanbanCardField, KanbanCardFieldLabel, KanbanCardFieldValue

The body is a two-column grid, hidden in `compact`: the label column takes the width of the widest `KanbanCardFieldLabel`, with 8px before the values. Each `KanbanCardField` is one row, a `div` that spans both columns. `KanbanCardFieldLabel` is a muted `span` for an icon and a label; `KanbanCardFieldValue` is a `div` for the value.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `interactive` | `boolean` | `false` | On `KanbanCardFieldValue`: when true, raises the value above the open trigger, for a select or another control. |

Each takes every prop of its element.

| Attribute | Values | Description |
| --- | --- | --- |
| `data-slot` | `"card-panel"` | Selects the body |
| `data-slot` | `"kanban-card-field"`, `"kanban-card-field-label"` or `"kanban-card-field-value"` | Selects a field and its two cells |
| `data-kanban-card-action` | `""` on an `interactive` value | Raises it above the open trigger |

### KanbanCardFooter, KanbanCardControl

The footer is a row at least 36px tall, in `text-xs`, hidden in `compact`. `KanbanCardControl` is a `span` that holds controls, such as count menus or the assignee, above the open trigger. Each takes every prop of its element.

| Attribute | Values | Description |
| --- | --- | --- |
| `data-slot` | `"card-footer"` or `"kanban-card-control"` | Selects the footer and a control |
| `data-kanban-card-action` | `""` on `KanbanCardControl` | Raises it above the open trigger |

In `compact` the footer is hidden, so put a part that must stay, such as the assignee, in the header.

## KanbanCardSkeleton

A loading card. Renders an `output`, whose role is `status`, named by `label`, with `aria-busy="true"` and no box of its own (`display: contents`); inside it, a `KanbanCard` hidden from assistive technology, with no pointer events. Its lines have the real line heights of the card parts, so a card with the same parts keeps the height of the skeleton.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `label` | `string` | `"Carregando card"` | Names the `status`. |
| `descriptionLines` | `number` | `2` | Sets the description lines; `0` removes them. |
| `fields` | `number` | `0` | Sets the rows of the body; `0` removes it. |
| `counts` | `number` | `1` | Sets the count buttons of the footer. |
| `assignee` | `boolean` | `true` | When true, adds a round avatar to the footer, or to the header in `compact`. |
| `menu` | `boolean` | `false` | When true, adds a square for the header menu. |

Also takes the props of `KanbanCard` (`display`, `density`, `selected`, `dimmed`), except `children`, `role`, `title`, `aria-busy` and `aria-label`. With no `counts` and no `assignee`, the footer is left out.

| Attribute | Values | Description |
| --- | --- | --- |
| `data-counts` | the number of count buttons | Reports `counts` on the `output` |
| `data-description-lines` | the number of description lines | Reports `descriptionLines` on the `output` |
| `data-fields` | the number of body rows | Reports `fields` on the `output` |

`KanbanView` renders it from `loadingCardAnatomy`, which takes the same fields except `label`.

## Accessibility and theme

- Name `KanbanCardOpenTrigger` and every icon-only control in the card with `aria-label`; pass `getCardLabel` so the drag handles read the card name instead of its key.
- The built-in texts are Portuguese (`Nenhum item nesta coluna.`, `Carregando card`, `Mover card`, `Adicionar item à seção`, `Configurar seção`, `Coluna`); pass the labels to change them.
- Columns are `region` landmarks named by their headings, so keep column titles distinct.
- The column surface is `card` and its border `border`, tinted by `color`; the card is the theme's `Card`, with `primary` for the focus and selection rings.
