# Instalação

O CLI é o pacote `@tc96/cli`, com o comando `tc96`.

## Requisitos

- React 19, TypeScript e Tailwind CSS 4.
- Um monorepo Bun no layout do tc96-mono, ou qualquer workspace com um `components.json` na raiz.
- Node e npm para executar o CLI. Bun não é exigido.

## Estrutura padrão

O padrão é o layout do tc96-mono: um pacote `@tc96/ui` guarda todas as camadas e
o `@tc96/utils` guarda o `cn`. Os pacotes resolvem pelos `exports`, sem `paths`
no `tsconfig`:

```text
packages/ui/src/
  components/   COSS e os componentes do tc96 que o COSS não tem (Text, IconFrame)
  hooks/ lib/   hooks e módulos dos componentes
  helpers/      funções sem React
  patterns/     patterns do tc96
  blocks/       blocks do tc96
packages/utils/ cn
```

Rode uma vez na raiz do monorepo:

```sh
npx @tc96/cli init
```

O `init` grava o `components.json` com esse layout e acrescenta ao
`packages/ui/package.json` os `exports` de camada que faltam. Um
`components.json` que já existe é mantido.

```json
{
  "aliases": {
    "components": "@tc96/ui",
    "ui": "@tc96/ui",
    "utils": "@tc96/utils",
    "lib": "@tc96/ui/lib",
    "hooks": "@tc96/ui/hooks",
    "helpers": "@tc96/ui/helpers",
    "patterns": "@tc96/ui/patterns",
    "blocks": "@tc96/ui/blocks"
  }
}
```

## Instalar em outro lugar

Para mudar o destino de uma camada, edite o alias dela no `components.json`.
Cada alias precisa resolver pelos `exports` do pacote do workspace que o contém
(`"./patterns/*": "./src/patterns/*.tsx"`) ou por uma entrada em `paths` no
`tsconfig` da raiz (`"@acme/ui/patterns/*": ["./packages/ui/src/patterns/*"]`).
Sem `hooks` e `lib`, esses arquivos vão para dentro do diretório de `ui`; sem
`helpers`, `patterns` ou `blocks`, o alias troca o último segmento do `ui`.
O CLI reescreve os imports para os seus aliases e instala as dependências npm no
pacote do workspace que contém o diretório de `patterns`.

Se você usa o shadcn, o `shadcn init --force` regrava o `components.json` sem as
chaves do tc96 e troca o alias `ui`. Se rodar esse comando, acrescente as chaves
de novo e revise o `ui`.

## Instalar

Instale um ou vários patterns de uma vez:

```sh
npx @tc96/cli add collection-views properties
```

Para instalar o checklist isoladamente, use `npx @tc96/cli add checklist`.

Os widgets de finanças, produtividade, CRM e gamificação vêm juntos em `npx @tc96/cli add widgets`. Os gráficos de saldo, progresso de tarefas e fluxo de caixa usam `recharts`, instalado como dependência do pattern.

O editor de texto estilo Notion vem em `npx @tc96/cli add rich-text-editor`. Ele usa o Plate headless (`platejs` e os plugins `@platejs/basic-nodes`, `@platejs/list-classic`, `@platejs/slash-command` e `@platejs/combobox`), instalados como dependências do pattern.

Os componentes de `ui` que os patterns usam e que faltam no seu projeto vêm
junto com o próprio CLI, sem acessar a rede. Os componentes que você já tem
ficam como estão, inclusive os personalizados.

Alguns componentes declaram tokens de tema, como o `--info` do `badge` e o
`--animate-skeleton` do `skeleton`. O CLI não edita o seu CSS: procura cada
token no arquivo de `tailwind.css` do `components.json` e lista os que não
encontrar, prontos para copiar.

### Regras de tema do menu

O `menu` e o `context-menu` dependem de duas regras no CSS do seu tema, que o
CLI não grava. Copie-as para o arquivo de `tailwind.css` do `components.json`:

```css
[role^="menuitem"][data-slot^="menu-"]:focus-visible,
[role^="menuitem"][data-slot^="context-menu-"]:focus-visible {
  outline: 2px solid var(--ring);
  outline-offset: -2px;
}

[data-slot="menu-shortcut"],
[data-slot="context-menu-shortcut"] {
  color: var(--muted-foreground);
}
```

- Sem a primeira, o foco de teclado num item aparece só pelo realce do COSS
  (`bg-accent`), que mede 1,09:1 contra o `--popover` no claro. O contorno mede
  4,73:1 no claro e 3,52:1 no escuro.
- Sem a segunda, o atalho (`MenuShortcut`, `ContextMenuShortcut`) fica com o
  `/72` do COSS e mede 3,14:1 no claro. Com o token cheio, 5,73:1 no claro e
  5,10:1 no escuro.

As medidas são do tema de exemplo; com outro tema, meça de novo.

O CLI grava os arquivos, reescreve os imports para os seus aliases e instala as
dependências npm que faltam com o gerenciador do seu lockfile (bun, pnpm, yarn
ou npm). Depois, gera o `index.ts` no diretório de `patterns`, que exporta todos
os patterns instalados, inclusive os de execuções anteriores:

```tsx
import { CollectionViewOutlet, TextProperty } from '@tc96/ui/patterns'
```

Arquivos existentes que diferem são preservados. Num terminal, o CLI pergunta
antes de sobrescrever cada um; com `--yes` ou sem terminal, preserva sem
perguntar. `--dry-run` lista o que mudaria, `--view` mostra os arquivos novos e
`--diff` as diferenças nos existentes, sem gravar nada.
O `index.ts` é do CLI e é regravado a cada `add`. Se você já tinha um
`index.ts` seu nesse diretório, o CLI não mexe nele e avisa para exportar os
patterns instalados por conta própria.

## Atualizar

Não há pacote para atualizar. Compare os arquivos instalados com a versão atual
e incorpore as correções manualmente:

```sh
npx @tc96/cli add collection-views --diff
```

Filter Builder não faz parte desta versão.
