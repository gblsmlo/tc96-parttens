# Instalação

> O nome do CLI no npm ainda não foi confirmado.

## Requisitos

- React 19, TypeScript e Tailwind CSS 4.
- COSS configurado, com `components.json` na raiz do monorepo. É o arquivo que o `shadcn init` cria; o CLI só o lê e não precisa do shadcn.
- Node e npm para executar o CLI. Bun não é exigido.

## Aliases

O tc96 instala as camadas dentro de um único pacote `ui`, no layout de monorepo
do shadcn:

```text
packages/ui/src/
  components/   COSS
  elements/     componentes que o COSS não tem
  helpers/      funções sem React
  patterns/     patterns do tc96
  lib/utils.ts  cn
```

```json
{
  "aliases": {
    "components": "@acme/ui/components",
    "ui": "@acme/ui/components",
    "utils": "@acme/ui/lib/utils"
  }
}
```

`elements`, `helpers` e `patterns` são derivados do `ui` trocando o último
segmento (`@acme/ui/elements`, `@acme/ui/helpers`, `@acme/ui/patterns`).
Declare-os em `aliases` só para pôr uma camada em outro lugar, como um pacote
`@acme/patterns` separado.

Cada alias também precisa de entrada exata e de wildcard em `paths` no
`tsconfig` da raiz (`"@acme/ui/patterns/*": ["./packages/ui/src/patterns/*"]`),
e o `exports` do `package.json` do `ui` precisa cobrir cada camada. O CLI grava
`elements`, `helpers` e `patterns` no diretório que o wildcard de cada alias
resolve, reescreve os imports para `ui` e `utils`, que continuam sendo seus, e
instala as dependências npm no pacote do workspace que contém o diretório de
`patterns`.

Se você usa o shadcn, o `shadcn init --force` regrava o `components.json` sem `elements`, `helpers`
e `patterns`, e troca o alias `ui`. Se rodar esse comando, acrescente as três
chaves de novo e revise o `ui`; o CLI avisa quando elas faltam.

## Instalar

Instale um ou vários patterns de uma vez:

```sh
npx @tc96/parttens add collection-views properties
```

Para instalar o checklist isoladamente, use `npx @tc96/parttens add checklist`.

Os widgets de finanças, produtividade, CRM e gamificação vêm juntos em `npx @tc96/parttens add widgets`. Os gráficos de saldo, progresso de tarefas e fluxo de caixa usam `recharts`, instalado como dependência do pattern.

O editor de texto estilo Notion vem em `npx @tc96/parttens add rich-text-editor`. Ele usa o Plate headless (`platejs` e os plugins `@platejs/basic-nodes`, `@platejs/list-classic`, `@platejs/slash-command` e `@platejs/combobox`), instalados como dependências do pattern.

Os componentes de `ui` que os patterns usam e que faltam no seu projeto vêm
junto com o próprio CLI, sem acessar a rede. Os componentes que você já tem
ficam como estão, inclusive os personalizados.

Alguns componentes declaram tokens de tema, como o `--info` do `badge` e o
`--animate-skeleton` do `skeleton`. O CLI não edita o seu CSS: procura cada
token no arquivo de `tailwind.css` do `components.json` e lista os que não
encontrar, prontos para copiar.

O CLI grava os arquivos, reescreve os imports para os seus aliases e instala as
dependências npm que faltam com o gerenciador do seu lockfile (bun, pnpm, yarn
ou npm). Depois, gera o `index.ts` no diretório de `patterns`, que exporta todos
os patterns instalados, inclusive os de execuções anteriores:

```tsx
import { CollectionViewOutlet, TextProperty } from '@acme/patterns'
```

Arquivos existentes que diferem são preservados. Num terminal, o CLI pergunta
antes de sobrescrever cada um; com `--yes` ou sem terminal, preserva sem
perguntar. `--dry-run` lista o que mudaria, `--view` mostra os arquivos novos e
`--diff` as diferenças nos existentes, sem gravar nada.
O `index.ts` é do CLI e é regravado a cada `add`. Se você já tinha um
`index.ts` seu nesse diretório, o CLI não mexe nele e avisa para exportar os
patterns instalados por conta própria.

## Atualizar

Não há pacote para atualizar. Compare os arquivos instalados com a versão atual
e incorpore as correções manualmente:

```sh
npx @tc96/parttens add collection-views --diff
```

Filter Builder não faz parte desta versão.
